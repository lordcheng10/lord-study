系统设计题 + 68 天收官

昨天(Day 67)把概念题逐条过了一遍。今天(Day 68)是最后一天：先教你怎么答"设计一个客服/文档 Agent"这类系统设计题(一套需求澄清→架构→检索/工具→评测→成本→上线的答题框架)，用它现场演练一遍；再带你回望全程 68 天你都学到了什么、织成了怎样一张能力网；最后给你一份能立刻照着做的下一步行动清单。这一天走完，你就毕业了。🎓

📍 阶段 12（实战求职 D62-68）· 你已抵达全程终点
D65 GitHub/博客→ D66 简历包装→ D67 概念题→ D68 系统设计+收官 🎓 终点
💡 用一个类比兜住今天（今天全程沿用「盖房子」的世界观） 系统设计题就像面试官说"给我设计一栋房子"。新手抓起笔就画墙，高手先问："住几口人？预算多少？在哪块地？"(需求澄清)——然后才出户型图(架构)、定水电走线(检索/工具)、说怎么验收(评测)、算造价(成本)、讲怎么交房(上线)。系统设计题考的不是你会不会砌墙，而是会不会当一个想清楚全局、还懂取舍的"包工头"。今天你就练这个。

L01

系统设计题：先别急着画架构图

🤔 痛点面试官抛出"设计一个公司内部文档问答 Agent"，很多人立刻开始背技术栈("用 LangChain + 向量库 + GPT……")。可你连"给谁用、多少文档、要多准"都没问，等于没看图纸就开始盖房——注定跑偏。
💡 本质系统设计题没有标准答案，考的是你的思考过程和取舍能力。面试官想看你像个真正的工程师那样：先搞清需求，再分层设计，每一步都能说"为什么这么选、代价是什么"。一套固定框架能让你永远不慌——照着 6 步走，题目再陌生也接得住。
图注：这 6 步就是今天 L02~L04 的骨架。答题时把它们说全，就已经赢过一半人。
👶 我怕说错，能不能就把这 6 步背下来照念？可以先背框架，但别背成"念稿"。面试官最想看到的是你边想边说、会停下来问问题、会说"这里有 A、B 两个方案，我选 A 因为……"。框架是骨架，取舍和提问是血肉。哪怕某一步你不熟，说"这块我会先查资料/做小实验验证"也比硬编强。
L02

第①②步：需求澄清 & 架构分层

🤔 痛点需求一模糊，后面全白搭。"文档 Agent"——是给客服用还是给员工用？文档 10 份还是 10 万份？要求秒回还是能等？错一次的代价多大？不问清楚，你的架构就是空中楼阁。
💡 本质第一步永远是提问(像装修前量房)。问清楚后，把系统切成几层：入口层→编排层(Agent 大脑)→能力层(检索/工具)→模型层→数据层→观测层。分层讲，思路才清晰、面试官才跟得上。
📝 举个例子：需求澄清该问哪些问题（挑 3~5 个问，别一口气全问）
  • 谁用、干嘛：内部员工查制度？还是对外客服答疑？(决定语气、权限、容错度)
  • 数据规模与更新：多少文档？多久更新一次？(决定要不要重建索引、增量更新)
  • 准确度要求：答错的代价多大？(高风险场景要加 Critic 校验、要能说"不知道")
  • 延迟与并发：要秒回吗？同时多少人用？(决定要不要缓存、流式输出)
  • 预算：能用贵模型吗？(决定模型选型和路由策略)
图注：这张分层图是"万能模板"——客服 Agent、文档助手、研究助手都能套，只改能力层的工具。
L03

第③④步：检索/工具选型 & 评测方案

🤔 痛点架构画完，面试官会追问细节："文档怎么切？检索不准怎么办？你怎么知道它答得对？"——这里最能区分"看过教程"和"真上过手"。答不出评测方案，基本等于没做过真项目。
💡 本质③检索/工具 = 决定 Agent"手上有哪些能力、怎么用得准"(把前 60 天的 RAG + 工具知识落地)；④评测 = "凭什么说它做得好"(整个课程反复强调的重中之重)。能主动讲评测，是这道题的最大加分项。
环节关键决策参考答法(带取舍)
切块怎么切、多大按语义/段落切+overlap；标题类短文档整块留。太大噪声多、太小语义断
检索怎么提准确率向量+BM25 混合召回，再 rerank 精排 top-k；按部门/权限做元数据过滤
工具Agent 要哪些手查订单/工单、转人工、提交表单；描述清晰、幂等、错误结构化返回
防幻觉怎么不瞎编"只据资料答、没有就说不知道"+带引用ID+Critic 校验高风险回答
评测怎么验收攒 golden set；检索看 hit rate/MRR，生成看 faithfulness/相关性；接 CI 回归
📝 举个例子：一句话把"评测闭环"讲漂亮 "我会先攒 50~100 条真实问题+标准答案做成 golden set。每次改 prompt 或换模型，都自动跑一遍：检索层看命中率(MRR)，回答层用 LLM-as-Judge 打忠实度和相关性分。这套评测接进 CI，分数掉了就拦住合并——保证每次上线都是'有数据证明变好了'，而不是凭感觉。" —— 这段话直接体现你懂"评测驱动"，是资深味道。
🔗 RAG 检索细节想答得更深？回看《LlamaIndex 20 天 RAG 精讲》→（这是本课检索/评测的深潜篇）
L04

第⑤⑥步：成本核算 & 上线运维

🤔 痛点Demo 能跑不代表能上线。面试官会问"一天几万次调用，这成本受得了吗？""上线后崩了怎么办？"——答不出成本和运维，说明你只做过玩具，没做过产品。
💡 本质⑤成本 = 把"钱和延迟"算明白(像盖房算造价与工期)；⑥上线 = 让它"稳、可控、出事能发现"(像交房后还得保修)。这两步体现你有产品思维和工程责任感，是高级信号。
图注：成本与上线正是本课 S9~S11(评测/可观测/部署)的落点，把它们串进系统设计答案里最显功力。
📝 举个例子：省钱三板斧一句话带过 "成本上我会做三件事：① 缓存——重复/相似问题直接命中缓存不再调模型；② 模型路由——简单问题走便宜模型、复杂的才上贵模型；③ 控上下文——检索精一点、历史做摘要，别让 token 无谓膨胀。再加个预算闸，超额告警。"

👶 小白：系统设计题我要不要把每一层的具体技术选型(哪个向量库、哪个模型)都说死？

👨‍🏫 老师：不要说死，要给选项+理由+取舍。比如向量库："小规模用 FAISS 够了，要多人协作和过滤就上 Qdrant/pgvector"——这比直接说"用 Milvus"高级得多，因为你展示了"我知道有哪些选择、也知道什么场景选什么"。面试官怕的不是你不知道某个具体工具，而是你只知道一个工具、不知道为什么用它。记住:系统设计考的是判断力，不是背诵力。

L05

实战演练：3 分钟答完"设计一个客服 Agent"

🤔 痛点框架看懂了，一到嘴上还是散。得有一份"标准示范",照着它把 6 步串成一段流畅的话,练到脱口而出。
💡 本质下面是一份可照着念的"满分口述模板"(以客服 Agent 为例)。你把里面的场景换成你自己的项目,就是一份现成的答案。建议大声读 3 遍。
🎤 满分口述示范（约 3 分钟）

①先澄清：我想先确认几点——这个客服 Agent 是对外用户还是内部坐席辅助？知识来源是产品文档还是工单历史？答错的代价高不高、要不要能转人工？大概多少并发、预算如何？(假设：对外、基于产品文档+订单系统、要求准、能转人工、中等并发)
②架构：我会分六层——入口层(聊天窗，鉴权限流、流式返回)、编排层(Agent 主循环，带护栏)、能力层(RAG 检索文档 + 查订单/转人工工具)、模型层(带路由)、数据层(向量库+原文)、观测层。
③检索/工具：文档按语义切块加 overlap；检索用向量+关键词混合再 rerank；订单查询等做成描述清晰、幂等、错误结构化的工具；答案要求只据资料回答、带出处，高风险回答过一遍 Critic 校验。
④评测：攒一批真实问答做 golden set，检索看命中率、回答用 LLM-as-Judge 看忠实度与相关性，接进 CI 做回归，分数掉了就拦。
⑤成本：缓存高频问题、简单问题走便宜模型、控上下文长度，设预算告警。
⑥上线：加降级兜底和危险动作审批，上线后监控 token/延迟/错误率/输出漂移，灰度放量、可回滚。
最后我会强调：先做一个最小可用版本跑通端到端，再用评测数据一轮轮迭代，而不是一上来就追求完美。

👶 这一段能套到别的题吗？能。把"客服"换成"文档助手""研究助手""代码助手",六步骨架完全不变,只改能力层的工具和数据。一套框架,应对一整类系统设计题。这就是为什么今天不让你背答案、而让你记框架。
L06

68 天全程复盘：你织成了怎样一张网

🤔 痛点68 天信息量巨大,容易"学了后面忘了前面"。收官这一刻,该把珠子串成项链——看清每一阶段在整张能力网里的位置,你才真正"拥有"它。
💡 本质回头看,这 68 天不是零散的知识点,而是一条从"不会编程"到"能设计并交付一个可信 Agent 系统"的完整链路。像盖房:先打地基(编程),再懂材料(大模型),学砌墙手艺(提示词/RAG/工具),搭骨架(Agent/框架/多智能体),做质检与安防(评测/可信),最后交房入住(部署/求职)。
阶段你学会了一句话价值

📝 一句话自检：你现在应该能…… 独立说清 RAG/Agent/评测的原理与取舍(Day67) · 照六步框架答系统设计题(今天) · 拿出 3 个作品集项目(Day62-64) · 有一份量化的简历(Day66) · 有 GitHub 和一篇设计博客(Day65)。能对上大半,你就具备了投递初级 Agent 工程师岗位的实力。
L07

下一步行动清单：从今天到拿到 offer

🤔 痛点学完最怕的是"合上教程,不知道下一步干嘛",热情慢慢凉掉。转行不是"学完就完",而是"学完立刻动起来"。
💡 本质把"找工作"也当成一个可迭代的项目:小步投递→收集反馈→修正简历/补短板→再投。像 Agent 的主循环:投递(行动)→面试反馈(观察)→调整(再决策)。下面是可直接照做的清单。

📤 求职行动（本周就开始）

  • 作品先行：确保 Day62-64 三个项目里至少 1 个在 GitHub 上有清晰 README + demo 录屏。
  • 简历定稿：用 Day66 的 STAR(问题→方案→指标)写好,数字量化,一页纸。
  • 小步投递：先投 5~10 家练手,别一次投完;每次面试后记下被问倒的题,回来补。
  • 去看岗位：对照岗位要求反推还差什么(💼 岗位分析页)。
  • 模拟面试：找朋友/用 AI 陪练,把 Day67 概念题 + 今天系统设计口述练到流畅。

📚 持续学习（长期,别停）

  • 深潜源码：挑一个最感兴趣的方向深入——RAG 看《LlamaIndex 精讲》、编排看《LangGraph 精讲》、可信工程看《gov-agents 精讲》、网关看《Higress/APISIX 精讲》。
  • 跟进前沿：这行变化快,养成读官方文档/发布说明的习惯(概念稳、API 常变)。
  • 持续产出：每做一个小项目就写一篇博客讲"设计取舍",作品和影响力一起攒。
  • 参与开源：给用过的开源 Agent 项目提 issue/PR,既学习又是简历亮点。
心态提示:转行不会一投就中,被拒很正常。把每次面试当成免费的"能力体检"——它告诉你哪块弱,补上再战。坚持迭代的人,最后都上岸了。
