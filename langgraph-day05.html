Day 05 / 共 20 天 · 第 1 周收官

一次 invoke 的完整旅程

把前四天串成故事线：一次 graph.invoke()，输入怎么流入状态、超步怎么推进、节点怎么跑、路由怎么走、循环怎么转、结果怎么出。

L01

追踪一段代码

# 一个 ReAct 风格的小图（我们追踪它的 invoke）
class State(TypedDict):
    messages: Annotated[list, add_messages]

builder = StateGraph(State)
builder.add_node("agent", call_llm)     # 调 LLM
builder.add_node("tools", run_tools)    # 执行工具
builder.add_edge(START, "agent")
builder.add_conditional_edges("agent", should_continue)  # 要工具→tools，否则→END
builder.add_edge("tools", "agent")      # 回头边=循环
graph = builder.compile()

graph.invoke({"messages": [("user", "北京天气?")]})   # ← 追踪这一行
读法：一个经典 ReAct 图：agent 节点 + tools 节点 + 条件边（判断要不要工具）+ 回头边（循环）。下面逐超步追踪 invoke 的执行。
L02

① 输入灌入 State

1
输入进 START 通道：{"messages": [用户问题]} 通过特殊 START 通道分发到 State 的 messages 键（经 add_messages reducer 写入）。
2
START → agent：START 边点亮 agent 的触发通道（Day 04），agent 成为超步 1 要跑的节点。
读法：invoke 的输入被 START 通道分发进共享 State，然后 START→agent 的边让 agent 待执行。此刻超步 0 结束，进入超步 1。
L03

② 超步 1：跑 agent

1
Plan：Pregel 引擎（Day 06）发现 agent 的触发通道被更新了，选它执行。
2
Execution：agent 节点读 State（messages），调 LLM，LLM 输出"我要调 get_weather 工具"，节点返回 {"messages": [带 tool_calls 的 AI 消息]}。
3
Update：超步末，用 add_messages reducer 把 AI 消息追加进 State.messages。
读法：超步 = Plan（选节点）→ Execution（并行跑）→ Update（写回状态）三阶段（Day 06）。agent 跑完，State 里多了一条带 tool_calls 的 AI 消息。
L04

③ 路由决定去向

1
条件边触发：agent 有条件边，路由函数 should_continue 读 State——最后一条消息有 tool_calls → 返回 "tools"。
2
点亮 tools：路由结果翻译成"往 tools 的触发通道写"（Day 04）→ tools 成为超步 2 要跑的节点。
路由就是"看状态决定下一步" agent 跑完，条件边的路由函数看 State 里最新的 AI 消息："它带了 tool_calls，说明想调工具" → 路由到 tools 节点。如果 AI 消息没有 tool_calls（直接回答了），就路由到 END。这就是 Agent"要不要继续"的判断——完全基于状态。
L05

④ 超步 2：跑 tools

1
Plan：引擎发现 tools 触发通道更新，选它跑。
2
Execution：tools 节点读 State 里的 tool_calls，执行 get_weather(北京)，得到"25℃"，返回 {"messages": [Tool 结果消息]}。
3
Update：Tool 消息追加进 State.messages。
读法：tools 节点执行工具、把结果作为 Tool 消息追加进 State。现在 State.messages 有：用户问题 + AI(要调工具) + Tool(25℃)。
L06

⑤ 循环回 agent

1
回头边：add_edge("tools", "agent") → tools 跑完点亮 agent 触发通道 → 超步 3 又跑 agent。
2
agent 再判断：agent 读 State（现在有工具结果了），调 LLM。LLM 看到"25℃"，生成最终答案"北京今天 25 度"——不再带 tool_calls。
3
路由走 END：条件边路由函数发现最新 AI 消息没有 tool_calls → 返回 END → 图停机。
循环怎么结束？ 每轮 agent 后都判断"还要调工具吗"。前面轮次要（有 tool_calls），就去 tools、再循环回来。直到某轮 LLM 觉得信息够了、直接给答案（不带 tool_calls），路由就走 END，循环结束。是 LLM 自己决定何时停——这就是 ReAct 的自主性。Day 04 的回头边让它能循环，条件边让它能停。
L07

⑥ 结果流出

图停机后，invoke 返回最终的完整 State——{"messages": [用户问题, AI(要工具), Tool(25℃), AI(最终答案)]}。你取最后一条 AI 消息就是答案。

每步都存了检查点（如果配了 checkpointer，Day 11）：超步 0/1/2/3 之间各存一次快照。所以这次运行能被恢复、时间旅行、或在中间中断等人工。整个旅程 = 输入灌入 State → 超步循环（Plan/Execution/Update）+ 路由 + 回头边 → LLM 决定结束 → 返回最终 State。这就是 LangGraph 执行一个 Agent 的全貌。
