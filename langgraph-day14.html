人在环 Human-in-the-loop

Agent 落地最关键的能力之一：让 AI 在关键处停下来问人。今天看动态 interrupt() 怎么在节点内部暂停要输入，Command(resume=...) 怎么送回答案继续。

📍 你在整门课的位置
时间旅行→人在环→记忆·序列化→react_agent
L01

为什么要人在环

🤔 痛点：危险操作（转账、删库）总不能让 AI 自己拍板吧？LLM 会幻觉、会误判。真放它无人值守地执行"转账 $10000""DROP TABLE"，一旦出错就是事故。可你又不想退回"全程人工"——那 Agent 就没意义了。你要的是：99% 自动，1% 关键处停下来等人点头。
💡 本质：interrupt() 把"暂停等人"变成一次普通函数调用底层复用检查点：节点跑到 interrupt() 就存档并交还控制权，人给了答案后靠重放从原地"接着跑"。写代码的人只看到"调了个函数、拿到人给的值"，跨越时间的暂停/恢复被完全封装了。

纯自动 Agent 在高风险场景不可接受：转账、删数据、发邮件、医疗建议……需要人类在关键节点审批/补充信息。Day 13 的静态断点太粗（只能在节点边界停），interrupt() 提供节点内任意位置的动态暂停。

回到 Day 01 的主题：LangGraph 的定位是"可控编排 + 局部 AI 自主"。人在环正是"可控"的极致体现——把人类判断力嵌进 AI 的执行流。这是 OpenHands、crewAI 等也都在做的能力，但 LangGraph 靠检查点做得最干净。
L02

interrupt()

interrupt(value)（langgraph/types.py def interrupt L811）在节点函数内部调用，暂停执行并把 value 抛给外部（作为"要问人的问题"）：

interrupt 暂停存档 → 人工审批 → Command(resume) 重放续跑
from langgraph.types import interrupt

def approve_node(state):
    # 执行到这里暂停，把这个 dict 抛给调用方，等人回答
    decision = interrupt({"question": "批准转账 $1000 吗？", "amount": 1000})
    # ↓ 人回答后，从这里"接着"往下（decision = 人给的值）
    if decision == "yes":
        return {"status": "approved"}
    return {"status": "rejected"}
读法：interrupt() 像一个"魔法暂停点"：第一次执行到它 → 暂停、把问题抛出去；人回答后重新执行 → interrupt() 直接返回人给的值，代码接着往下。写起来像普通函数调用，行为却是"跨越时间的暂停/恢复"。
L03

暂停原理

interrupt() 内部其实是抛出一个特殊异常 GraphInterrupt。Pregel 捕获它 → 停止本超步、把 interrupt 的 value 存进检查点、invoke 返回一个含 __interrupt__ 的结果。

💬 小白 vs 老师：抛异常不就"报错崩了"吗，怎么还能续？ 👶 小白：interrupt() 抛了个异常，那这次运行不就挂了？后面咋接着跑？
👨‍🏫 老师：关键是这个异常被引擎自己接住了，不会冒到你面前。引擎接住后顺手存了检查点、把 invoke 正常返回给你。等你回 Command(resume=...)，引擎重新跑一遍这个节点——这次跑到 interrupt() 不抛异常了，而是直接返回你给的值，代码就"接着"往下了。就像生活中游戏弹出"确定删除装备吗？"的确认框：游戏并没崩，只是卡在那等你点按钮，点了才继续。
"抛异常来暂停"——巧妙的实现 怎么让一个普通函数"跑到一半停住、以后还能从原地继续"？Python 没有原生的可保存续体。LangGraph 的办法：interrupt() 抛一个特殊异常，把执行"弹"回引擎，引擎顺势存检查点。人回答后重跑这个节点——但这次 interrupt() 不抛异常，而是返回人给的值。因为节点函数是纯的、可重放的（相同输入相同结果），从头重跑到 interrupt 处、跳过前面已知的部分，效果就等价于"从暂停处继续"。这也是为什么 LangGraph 要求节点无副作用或副作用幂等——它可能被重放。
L04

Command(resume=...)

人给出答案后，用 Command(resume=值)（langgraph/types.py class Command L759）作为 invoke 的输入恢复执行：

📝 例子：一个转账审批节点 
def approve_transfer(state):
    ok = interrupt({"question": "批准转账 $1000?", "amount": 1000})  # 暂停问人
    if ok == "yes":
        do_transfer(1000)            # 只有人点头后才真正执行（放 interrupt 之后！）
        return {"status": "done"}
    return {"status": "cancelled"}

app.invoke(input, cfg)               # → 停下，抛出 {"question":"批准转账 $1000?"...}
app.invoke(Command(resume="yes"), cfg)   # 人回 yes → interrupt 返回 "yes" → 执行转账
from langgraph.types import Command

# 第一次：跑到 interrupt 停下
result = graph.invoke({...}, cfg)
print(result["__interrupt__"])   # [{"question": "批准转账...", ...}]

# 人决定后：把答案通过 Command(resume=...) 送回去
graph.invoke(Command(resume="yes"), cfg)   # interrupt() 这次返回 "yes"
读法：Command(resume=x) 告诉引擎"上次暂停的 interrupt，人给的答案是 x"。重跑到那个 interrupt 时，它就返回 x。Command 还能带 update（改状态）、goto（跳节点）——是个统一的"控制指令"对象。
L05

恢复重放

恢复时（Day 11 恢复过程）：加载检查点 → 重跑被中断的节点 → 引擎把 Command.resume 的值喂给 interrupt() 让它返回 → 节点从暂停点"逻辑上继续"跑完 → 正常进入下一超步。

读法：恢复 = 重放（replay）。一个节点里若有多个 interrupt，引擎按索引依次匹配 resume 值。关键前提：interrupt 之前的代码会被重新执行一遍——所以别在 interrupt 前做"发邮件"这种不可重复的副作用（要放到 interrupt 之后，或确保幂等）。

把一次带审批的转账逐步走查一遍（thread 全程不变）：

步骤发生什么检查点 / 状态
1invoke(input, cfg) 进入 approve 节点，跑到 interrupt({"question":...})抛 GraphInterrupt，引擎接住
2引擎存检查点、暂停，invoke 返回 {"__interrupt__":[...]}✅ 检查点已落盘（含待答问题）
3程序把问题给人看，等待……（可以是几秒也可以是三天）状态静静躺在检查点里
4人决定："yes"。程序 invoke(Command(resume="yes"), cfg)从检查点加载状态
5重放 approve 节点：跑到 interrupt() 这次返回 "yes"（不抛异常）接着往下执行真正的转账
6节点返回 {"status":"done"}，进入下一超步直到结束✅ 存入新检查点，流程完成
读法：看第 5 步——同一个 interrupt()，第一次"抛异常暂停"，重放时"返回人给的值"，两种行为由引擎按有没有 resume 值切换。这就是"跨越时间继续"的全部秘密。
L06

完整例子

from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.types import interrupt, Command

def ask_human(state):
    name = interrupt("你叫什么名字？")     # 暂停问人
    return {"messages": [f"你好，{name}！"]}

g = StateGraph(State).add_node("ask", ask_human)
g.add_edge(START, "ask").add_edge("ask", END)
app = g.compile(checkpointer=InMemorySaver())   # ★ 人在环必须有 checkpointer

cfg = {"configurable": {"thread_id": "1"}}
app.invoke({"messages": []}, cfg)          # → 暂停，抛出 "你叫什么名字？"
app.invoke(Command(resume="小明"), cfg)     # → interrupt 返回 "小明"，输出 "你好，小明！"
读法：人在环必须配 checkpointer——因为暂停要靠检查点保存状态。没有它 interrupt 无处可存、无法恢复。这把第 3 周三个主题串起来了：检查点（存）→ 时间旅行（读任意存档）→ 人在环（在存档点等人）。
L07

四种常见模式

  • Approve/Reject（审批）：interrupt 抛出待办操作，人回 yes/no。
  • Edit State（编辑）：人审查后用 Command(update=...) 修改状态再继续。
  • Provide Input（补充信息）：AI 缺信息时 interrupt 向人要（如上例问名字）。
  • Review Tool Call（工具审查）：LLM 想调危险工具，interrupt 让人先审工具参数。
读法：四种模式底层是同一个 interrupt + Command 机制，只是 value 内容和 resume 用法不同。官方文档把它们列为标准 HITL 范式——你现在知道它们全是同一套检查点能力的应用。
