Day 01 / 共 20 天 · 第 1 周 核心概念

项目全景与 monorepo 架构

第一天建立全局认知：CrewAI 是什么、三个核心概念、Crew 和 Flow 两种范式的区别、monorepo 结构。不写难代码，只建直觉。

L01

它到底是什么

CrewAI 是一个 多智能体（multi-agent）编排框架。核心比喻是"组建一支团队"：与其用一个全能 AI 硬扛复杂任务，不如把任务分给一支各有专长的 AI 团队协作完成。

用最白的话说 想写一篇高质量的行业分析报告。一个 AI 硬做：又要查资料、又要分析、又要润色，样样都做但都不精。CrewAI 的做法：组一支"团队"——① 研究员 Agent 负责查资料；② 分析师 Agent 负责提炼观点；③ 写手 Agent 负责成文。每个 Agent 有明确角色，产出交接给下一个。分工 + 协作 = 比单个全能 AI 更专业、更可控的结果。这就是 CrewAI。
为什么它很火：CrewAI 是 GitHub 上最受欢迎的多智能体框架之一，API 直观（组队干活的比喻人人秒懂）、上手快、生态活跃。学它能理解"多个 AI 如何分工协作"这一核心命题——这是 Agent 领域最重要的方向之一。
L02

三个核心概念（先记住）

CrewAI 的一切都围绕三个概念，缺一不可：

  • Agent（智能体）：一个"员工"，有 role（角色）、goal（目标）、backstory（背景故事）。比如"你是资深财经记者，擅长把复杂数据讲成故事"。
  • Task（任务）：一件"活儿"，有 description（做什么）和 expected_output（期望产出啥）。
  • Crew（团队）：把 Agent 和 Task 组织到一起，按某种 Process（流程）执行。调 kickoff() 开工。
一句话记牢 Agent 是"人"，Task 是"活儿"，Crew 是"把人和活儿组队并开工的团队"。接下来的 Day 02/03/04 分别精讲这三个，Day 05 把它们串成一次完整运行。今天先把这个三角关系刻进脑子。
L03

一个最小例子（感受一下）

CrewAI 经典的写法长这样（概念示意，Day 02-05 逐行拆）：

from crewai import Agent, Task, Crew

# 1. 定义一个 Agent（员工）
researcher = Agent(
    role="资深行业研究员",
    goal="找到关于 {topic} 的最新、最可靠的资料",
    backstory="你在这个行业深耕十年，擅长辨别信息真伪。",
)

# 2. 定义一个 Task（活儿）
research_task = Task(
    description="研究 {topic} 的最新进展",
    expected_output="一份 5 条要点的资料清单",
    agent=researcher,
)

# 3. 组队并开工
crew = Crew(agents=[researcher], tasks=[research_task])
result = crew.kickoff(inputs={"topic": "AI Agent"})   # 开工！
print(result)
读法：定义员工（Agent）→ 定义活儿（Task，指定哪个员工做）→ 组队（Crew）→ kickoff 开工。注意 {topic} 是占位符，kickoff(inputs=...) 时填充——这让同一个 Crew 能处理不同输入。就这么直观。
L04

Crew vs Flow：两种范式

CrewAI 有两种搭建范式，理解区别很重要：

👥 Crew（团队）

  • 自主协作的 Agent 团队
  • 你定义角色和目标，Agent 自主决定怎么干
  • 适合开放、创造性的任务
  • 不确定性高，但灵活

🔀 Flow（工作流）

  • 事件驱动的确定性编排
  • 用 @start/@listen 精确控制步骤顺序
  • 适合流程固定、要精确控制的场景
  • 可以内嵌 Crew
怎么选？ Crew 像"给团队一个目标，放手让他们自己配合完成"——灵活但结果不完全可控。Flow 像"画一张精确的流程图，规定每一步先做什么、条件满足才做什么"——可控但需要你设计流程。实践中常组合用：Flow 控制大流程，某些步骤内部用 Crew 让 AI 自主发挥。前两周我们主攻 Crew（Day 02-10），第 3 周讲 Flow（Day 11-13）。
L05

monorepo 结构

CrewAI 是个 monorepo（单仓多包）——一个仓库里放多个独立的 Python 包，都在 lib/ 下：

crewAI/
└── lib/
    ├── crewai/        # ★ 核心包（Agent/Task/Crew/Flow/Process...）本教程主战场
    ├── crewai-core/   # 更底层的核心工具
    ├── crewai-tools/  # 官方工具库（搜索、文件、RAG 等）
    ├── crewai-files/  # 文件处理
    └── cli/           # 命令行工具（脚手架 crewai create）
monorepo 是什么？为什么这么组织？ monorepo = "一个 git 仓库里放多个可独立发布的包"。好处：① 核心（crewai）和工具（crewai-tools）能各自独立版本发布、独立安装（你只用核心就不用装一堆工具依赖）；② 但它们在一个仓库里，改动能一起测试、保持同步。核心逻辑全在 lib/crewai/src/crewai/——记住这个路径，这 20 天几乎都在读它。

L07

为什么"角色扮演"有用

CrewAI 让每个 Agent 都有 role + goal + backstory。这不是花架子——它是经过验证的提示词工程技巧。

给 AI 一个身份，它就"入戏"了 同一个问题，你对大模型说"回答这个"，和说"你是有 20 年经验的儿科医生，请回答这个"，得到的答案质量差很多。给定角色后，模型会：① 用该角色的专业视角和语气；② 聚焦相关知识；③ 保持一致的行为风格。backstory（背景故事）进一步强化人设。CrewAI 把这个技巧变成了框架的一等公民——每个 Agent 天生就有身份，产出自然更专业。这也是为什么它叫"角色扮演（role-playing）"多智能体框架。
多角色协作 > 单一全能：让"研究员"和"批判性审稿人"分别是两个 Agent，比让一个 Agent 又当运动员又当裁判效果好——不同角色能相互制衡、补充。这是多智能体相比单 Agent 的核心价值。
