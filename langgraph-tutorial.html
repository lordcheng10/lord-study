开篇 · 这是个什么框架

LangGraph 是 LangChain 团队推出的底层编排框架，用于构建有状态、多角色的 LLM 应用/智能体。核心思想：把智能体的工作流建模成一张"状态图"——节点是干活的函数、边是控制流、所有节点共享一份"状态（State）"。它由 Google 的 Pregel（图计算）模型驱动，天生支持持久执行、人在环、流式、记忆。

🎯 一句话：在 LangGraph 里，一个智能体 = 一张状态图（StateGraph）。你定义若干节点（函数，读共享状态、返回状态更新）和边（谁连谁、条件路由），编译后由 Pregel 引擎一"超步（super-step）"一超步地执行——节点通过通道（channels）通信，状态每步可被检查点（checkpoint）保存，从而能崩溃恢复、时间旅行、中断续跑。

预制 Agent

create_react_agent 开箱即用；也能降到裸 StateGraph 全定制。

关于它和 LangChain 的关系：LangChain 是"用 LLM 搭应用的工具箱"（模型、工具、链）；LangGraph 是"编排引擎"——它是 LangChain 生态里 Agent 的底层运行时。你可以用 LangGraph 的预制 create_react_agent 快速起步，也能降到裸 StateGraph 完全自定义控制流。前 5 天不假设你懂图/Pregel/状态机。源码在 libs/langgraph/langgraph/。

LangGraph 的心智模型是"节点 + 边 + 共享状态，Pregel 超步执行"——经典 ReAct Agent 就是一张小图：

agent 节点调 LLM
决定下一步→ 条件边要调工具吗? 是→ tools 节点 ↺ 回 agent 否→ END
为什么用"图"？ Agent 的控制流本质是"根据状态决定下一步做什么"——图（节点+条件边）天然表达这种控制流，还支持循环（Agent 反复调工具）、分支、并行。相比"一个大 while 循环"，图更清晰、可组合、可视化、可持久化。这和你学过的 eino Graph、AutoGPT Graph 一脉相承。
