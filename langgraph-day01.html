Day 01 / 共 20 天 · 第 1 周 核心概念

项目全景（与 LangChain 的关系）

第一天建立全局认知：LangGraph 是什么、和 LangChain 什么关系、为什么用"图"建模、核心概念、三层使用路径。

L01

它是什么

LangGraph 是 LangChain 团队出品的底层编排框架，一句话定位（README.md:12）："Low-level orchestration framework for building stateful agents"——构建有状态智能体的底层编排框架。

用最白的话说 它帮你把一个智能体的"工作流程"画成一张图：图上的节点是"干活的函数"（通常调 LLM 或工具），边决定"下一步走哪个节点"，所有节点共享一份状态（State）。你定义好这张图，LangGraph 负责一步步执行它。灵感来自 Google Pregel（图计算）、Apache Beam，API 借鉴 NetworkX（README.md:82）。五大能力：持久化执行（崩溃可恢复）、人在环（任意步检查/修改）、记忆、可视化调试、生产部署。
L02

和 LangChain 的关系（关键）

LangChain

  • 用 LLM 搭应用的"工具箱"
  • 模型、工具、链、预置 agent
  • 想快速用现成架构 → 用它

LangGraph

  • 底层编排引擎
  • 需要深度定制控制流、持久执行 → 用它
  • LangChain 的 agent 就构建在 LangGraph 之上
一句话记住 LangGraph = LangChain agent 底下的"图引擎"。（libs/langgraph/README.md:24）基础用法你用 LangChain 的现成 agent 就行（不用懂 LangGraph）；但当你需要"确定性 + AI 自主的混合流程、精细控制、持久执行"时，就降到 LangGraph 直接写图。它俩不是竞争，是分层——LangChain 在上（易用），LangGraph 在下（强大）。LangGraph 也能独立用。
L03

为什么用"图"建模

智能体的控制流本质是"根据当前状态决定下一步做什么"，还常有循环（反复调工具）、分支（不同情况走不同路）。图（节点+边）天然表达这种控制流。

图 vs 一个大 while 循环 你也能用一个 while 循环 + 一堆 if 写智能体。但流程一复杂（多个分支、循环、并行），代码就成一团乱麻。用图：每个节点是一个清晰的步骤，边明确表达"谁之后是谁、什么条件走哪"——流程一目了然、可组合、可可视化、可持久化（每步存快照）。而且循环就是"图里有一条回头边"（Agent → 工具 → 回到 Agent）。这和你学过的 eino Graph、AutoGPT Graph 同一思想——把控制流建模成图，是编排复杂 Agent 的主流方案。
L04

核心概念地图

  • StateGraph（状态图）：用户定义的图——节点 + 边 + 状态 schema。
  • Node（节点）：一个函数，读共享状态、返回"状态更新"。
  • Edge（边）：控制流——普通边（固定连接）、条件边（根据状态路由）。
  • State + Reducer（状态 + 归约器）：所有节点共享的状态，reducer 决定"更新怎么合并进状态"（如追加 vs 覆盖）。
  • Channel（通道）：状态在底层存为"通道"，节点通过通道通信（Day 07）。
  • Pregel：执行引擎，按"超步"驱动图（Day 06）。
  • Checkpoint（检查点）：状态快照，实现持久/恢复/时间旅行（Day 11）。
  • START / END：图的入口/出口特殊节点。
这些是后面 20 天的主角。核心记住：StateGraph（节点+边+状态）→ 编译成 Pregel → 超步执行 → 通道通信 → 检查点持久化。
L05

一个最小例子

from langgraph.graph import StateGraph, START, END
from typing import TypedDict

class State(TypedDict):     # 共享状态
    count: int

def increment(state: State):    # 一个节点：读 state、返回更新
    return {"count": state["count"] + 1}

builder = StateGraph(State)
builder.add_node("inc", increment)   # 加节点
builder.add_edge(START, "inc")       # START → inc
builder.add_edge("inc", END)         # inc → END
graph = builder.compile()            # 编译成可运行的图

result = graph.invoke({"count": 0})  # 跑！ → {"count": 1}
读法：定义状态（TypedDict）→ 写节点函数（吃 state、返回部分更新）→ 加节点和边 → compile → invoke。节点函数只返回"要改的那部分状态"（{"count": ...}），框架负责合并进完整状态（Day 03 的 reducer）。就这么直观。

L07

三层使用路径

LangGraph 提供三个抽象层级，从易到难：

  1. create_react_agent（预制）：一行代码起一个 ReAct Agent（Day 16）——开箱即用。
  2. ToolNode + tools_condition（半自定义）：用现成的工具节点和路由，自己接线（Day 17）。
  3. 裸 StateGraph（全自定义）：自己定义所有节点、边、状态——完全控制（Day 02-05）。
这个"三层"很贴心 新手用 create_react_agent 一行起 Agent；进阶用 ToolNode 拼自己的图；高手裸写 StateGraph 完全定制。层层递进——你可以从最简单的预制入手，需要更多控制时逐层往下降。本教程会都覆盖：前两周学裸 StateGraph 和引擎（理解底层），第 4 周学预制（快速上手）。先懂底层，再用糖——这样你既会用又懂原理。
