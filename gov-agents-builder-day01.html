Day 01 / 5 · 业务方构建 Agent

选型决策树 · 4 问定路线

开工前 30 分钟把路线定死：别写到一半才发现该做 Skill、该扩老 agent、或该走独立仓。

Q1

Skill 还是 Agent？

Skill = 一段 markdown SOP，IDE 的 LLM 读了照着做（curl/改文件/mvn），零安装。Agent = 打包的可执行 LangGraph 代码，确定性流程 + Nexus 版本 + Portal KPI。
信号偏 Skill偏 Agent
主要动作查/读/聚合/出报告改代码 / 多步状态机 / 调下游
正确性LLM 照做可接受必须确定性、可重放
Portal KPI不需要需要
版本/审计文本无版本锁Nexus + scope guard
💡 一句话教 LLM 怎么做 → Skill；打包好替你做 + 要 KPI → Agent。bmc-agent 升 Maven 必须确定性 → Agent；cost-audit 出报告 → Skill。
Q2

独立仓还是 Monorepo？

有 gov-agents-platform 仓写权限? ├── 否 → 路径 A · 独立仓（模板直链 / Portal zip） └── 是 → agent 会被多团队共用 / 进平台 CI? ├── 是 → 路径 B · Monorepo apps/<name>/ └── 否 → 仍推荐 路径 A（迭代更快）
路径 A 独立仓路径 B Monorepo
权限不需要平台仓需要 MR
依赖Nexus BOMworkspace 内 toolkit
发布uv publish → Nexus / obelisk平台 CI + canary

Q3

跟现有 Agent 重复吗？

开新仓前先对照平台已有 agent（节选）：

Agent场景
sre-rca-agent微服务根因分析
risk-reviewerPR 风险评审
alert-triage告警分流派单
doc-checker文档要点检查
biz-link-gov-agent业务链路治理
bmc-agentMaven parent 升级（独立仓）
  • 新需求 ⊂ 某 agent 80% → 扩 prompt / 加 SP，不开新 agent
  • 交集 ≤ 30% → 开新 agent
  • 30–80% 灰区 → 列重叠点，团队讨论
Q4

哪种起手方式？

方式适合
模板直链（免登录）独立仓 · 看得见每一步 · 推荐新手
Portal「新建 agent」向导要预览 LOC/cost · 沙箱 pytest

小结 + 下一步

  • 编排工具出报告 → Skill；确定性 + KPI → Agent
  • 没权限 / 本机敏感数据 → 路径 A 独立仓
  • 80% 重叠 → 扩老的；≤30% → 开新的
