Day 02 / 共 20 天 · 第 1 周 核心概念

Agent：角色扮演的智能体

第一个核心概念。Agent 是"会干活的员工"——由大模型驱动，有角色设定、工具、记忆，按 ReAct 循环反复思考行动。今天读 agent/core.py 的真实代码。

📍 你在整条链的位置（昨天建立了"团队分工"的全景，今天钻进第一个角色：员工 Agent）
Day1 全景→ Day2 Agent 员工（会干活的人）→ Day3 Task 工单→ Day4 Crew 组队→ Day5 kickoff 旅程
L01

Agent 的两层类结构

Agent 分两层（经典的"抽象基类 + 具体实现"）：

  • BaseAgent（agents/agent_builder/base_agent.py:200）：抽象基类，定义所有 agent 共有的契约（role/goal/backstory、execute_task 等抽象方法）。
  • Agent(BaseAgent)（agent/core.py:170）：CrewAI 官方实现，加上 LLM、执行时序、规划等。
为什么要分两层？ BaseAgent 定"合同"，Agent 是"官方员工"。把"任何 agent 都必须能做的事"（如"执行一个任务"）写进 BaseAgent 抽象方法，具体怎么做留给子类。好处：将来第三方想接入自己的 agent 实现（比如包装 LangChain 的 agent），只要满足 BaseAgent 的合同即可，Crew 照样能调度它。面向接口编程——和 eino/OpenHands 教程里反复见到的哲学一致。
L02

三个人设字段（Agent 的灵魂）

🤔 不给身份的 AI vs 给了身份的 AI 同一个问题"帮我看看这段代码有没有问题"，你两种问法：
① 直接问 → AI 泛泛回一句"看起来还行"；
② "你是有 15 年经验、极其挑剔的安全审计工程师，帮我审这段代码" → AI 立刻用专业视角逐行挑边界条件、注入风险。没有身份设定，AI 就像个没进入状态的临时工，产出飘忽又平庸。
💡 一句话本质 role/goal/backstory = 把"给 AI 一个身份"这个提示词技巧，固化成 Agent 的必填字段。类比给演员剧本：先告诉他"你演谁（role）、你要达成什么（goal）、你的来历（backstory）"，他才能入戏。CrewAI 逼你填这三项，等于逼你把角色说清楚。
# base_agent.py:263-265
role: str      = Field(description="Role of the agent")       # 角色，如"资深研究员"
goal: str      = Field(description="Objective of the agent")  # 目标
backstory: str = Field(description="Backstory of the agent")  # 背景故事
role + goal + backstory 三字段被拼进系统提示词，让 LLM "入戏"，再执行任务产出专业风格的结果。这就是 Agent 从"人设"到"行动"的链路。
📝 一个具体 Agent 定义 → 它入戏后的回答风格 定义：role="毒舌但专业的美食评论家"，goal="一针见血点评菜品"，backstory="你在米其林餐厅吃了20年，见惯山珍海味，最恨徒有其表的菜。"
问它"评价一下这盘番茄炒蛋" → 它不会平淡地说"还不错"，而会入戏成评论家口吻："火候尚可，但糖放多了掩盖了番茄的酸鲜——这是讨好外行的做法，及格线徘徊。"
→ 同样的 LLM，换个人设，语气、视角、专业度全变。
读法：三个必填字段构成 Agent 的"人设"。它们会被拼进系统提示词，让大模型"入戏"。role 定身份、goal 定目标、backstory 加背景增强代入感。
为什么这三个字段这么重要（Day 01 的呼应） 回忆 Day 01：给 AI 一个身份，它就"入戏"，产出更专业。这三个字段就是把"角色扮演"这个提示词技巧固化成 Agent 的必填属性——你无法创建一个没有角色的 CrewAI Agent。框架用"强制填写人设"的方式，逼你用好这个技巧。好的框架会把最佳实践变成默认路径。
💼 生活类比：定义 Agent 就像招聘一个员工 创建一个 Agent 就像生活中招人入职：role 是岗位名称（招"资深研究员"还是"文案"）；goal 是这个岗位的 KPI（你要达成什么目标）；backstory 是简历/人设（有什么经历、什么风格）。三样凑齐，这位"新员工"就知道自己是谁、要干嘛、以什么风格干——和你入职第一天读岗位说明书一模一样。
💬 小白 vs 老师 👶 小白：role 和 goal 感觉差不多啊，都是"干什么的"，为啥要分开？
👨‍🏫 老师：招聘时也分。role=岗位（"你是财务分析师"），goal=这次要达成的目标（"把 Q3 报表异常找出来"）。同一个岗位可以接不同目标——研究员这次研究 AI、下次研究新能源。
👶 小白：那 backstory 是不是可有可无的花架子？
👨‍🏫 老师：恰恰相反，它是"简历"，决定语气和专业深度。"科班出身、发过顶会"和"半路出家的爱好者"，同一个岗位答出来的东西质感天差地别。人设越具体，AI 入戏越深。

L04

占位符插值 interpolate_inputs

你可以在 role/goal/backstory 里写 {topic} 这样的占位符，运行时替换（base_agent.py:728 的 interpolate_inputs）：

researcher = Agent(role="{industry} 行业研究员", goal="研究 {topic}")
# kickoff(inputs={"industry":"AI","topic":"多智能体"}) 时，
# {industry}→"AI"、{topic}→"多智能体" 被自动填入
读法：占位符让同一个 Agent 定义能复用于不同输入。框架还保留 _original_role 等原值（base_agent.py:257）——因为插值是"每次运行时"做的，得留着模板原文，下次换输入再插值，不能把模板改没了。
为什么要保留原始模板？ 想象 role="{industry} 研究员"。第一次运行填成"AI 研究员"，如果直接改掉 role，第二次想填"金融研究员"就没模板了（role 已经变成"AI 研究员"）。所以框架把原始模板存在 _original_role，每次运行都从模板重新插值。"模板与实例分离"——一次定义、多次复用。
L05

初始化魔法 post_init_setup

你写 Agent(role=..., llm="gpt-4o")——注意 llm 传的是字符串。它怎么变成真正的模型对象？靠 Pydantic 的初始化后钩子（core.py:353）：

# core.py:356-363 —— @model_validator(mode="after") 构造后自动跑
self.llm = create_llm(self.llm)     # 字符串/字典 → BaseLLM 实例
if not self.agent_executor:
    self._setup_agent_executor()    # 初始化缓存 + 执行器
读法：你传字符串 "gpt-4o"，create_llm 自动把它解析成一个真正的 LLM 对象。这是"配置即代码"——用户写最简洁的声明式配置，框架负责把它实例化成可用对象。memory=True 也是同理自动建 Memory()。
这种"自动解析"体验为什么好？ 对比：如果框架要求你写 Agent(llm=LiteLLM(model="gpt-4o", api_key=..., ...))，很啰嗦。CrewAI 让你写 llm="gpt-4o" 就行，剩下的解析、配置、实例化全自动。把复杂留给框架，把简单留给用户——好 API 的标志。
L06

execute_task：Agent 怎么干一件活

入口 execute_task（core.py:740），分三步（模板方法式清晰分层）：

# 1. 准备 prompt（core.py:489 _prepare_task_execution）
#    注入日期、生成任务 prompt、拼接 context、检索记忆
# 2. 知识检索（core.py:764 handle_knowledge_retrieval）从知识库补充
# 3. 真正执行（core.py:859）——调执行器
invoke_result = self.agent_executor.invoke({
    "input": task_prompt,
    "tools": self.agent_executor.tools_description,
    "ask_for_human_input": task.human_input,
})
读法：准备提示词（拼角色+任务+上下文+记忆）→ 补充知识 → 交给执行器跑 ReAct 循环。执行器（AgentExecutor，Day 07 精读）才是真正反复"思考→用工具→观察"的地方。execute_task 只负责把料备齐、交出去、拿回结果。
超时与重试：设了 max_execution_time 就用线程池 + future.result(timeout=...)（core.py:826）跑，超时抛错；异步版用 asyncio.wait_for。出错走 _handle_execution_error（core.py:673）递归重试到 max_retry_limit。同步靠线程、异步靠事件循环——这是很好的并发对比教学点。ReAct 循环细节留到 Day 07。
L07

独立 kickoff：Agent 不用 Crew 也能跑

Agent 除了在 Crew 里被调度，还能单独运行（core.py:1522 的 kickoff）——内部临时构造执行器，返回轻量结果 LiteAgentOutput：

answer = researcher.kickoff("帮我总结这段文字的三个要点")   # 不需要 Task/Crew
# 更简单的一问一答：
reply = researcher.message("你好")   # core.py:715，临时建 Task+Crew
读法：简单场景不必搭完整的 Task+Crew，直接 agent.kickoff(...) 一问一答。贴心设计：kickoff 检测到自己处在异步事件循环里，会自动返回协程（core.py:1565），你不用手动区分同步/异步。
关于 LiteAgent：有个 lite_agent.py 的轻量 agent，但已标记 deprecated（v2.0 移除），官方建议改用 Agent().kickoff()。所以别用 LiteAgent，需要轻量就用 Agent 的 kickoff。
