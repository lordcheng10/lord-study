Day 01 / 共 20 天 · 第 1 周 RAG 全景与数据摄入

项目全景：RAG 与智能体框架

欢迎来到 LlamaIndex——把"你的私有数据"和"大模型"接起来的最流行框架。第一天先建立整体印象：什么是 RAG、为什么需要它、LlamaIndex 怎么把 RAG 全流程模块化。

L01

LlamaIndex 是什么

README.md：LlamaIndex 是"构建 agentic applications（智能体应用）的开源框架"。最经典的能力是 RAG——让大模型基于你的私有文档回答问题。

用一个场景理解 你有 1000 份公司内部文档，想做个"能回答文档内容的问答机器人"。直接问 ChatGPT 不行——它没见过你的文档。LlamaIndex 帮你：把这 1000 份文档"读进来、切成小块、变成向量存起来";用户提问时，先"检索"出最相关的几块，再连同问题一起喂给大模型生成答案。这就是 RAG，LlamaIndex 是做这件事最成熟的框架。新版还能做"智能体"——让大模型自己决定用哪些工具、多步推理。
L02

为什么需要 RAG

大模型的三个软肋，RAG 一并解决 ① 知识过时/有限：它没见过你的私有数据、也不知道最新信息。② 会"胡编"（幻觉）：不知道就瞎编。③ 不可溯源：说的话你不知道依据。RAG 的解法：先从你的资料库检索相关内容，再让大模型"看着这些资料"回答——等于开卷考试。于是：答得准（基于真实资料）、不胡编（有依据）、可溯源（能标出来自哪份文档）。这就是为什么企业做 AI 应用几乎都用 RAG，而 LlamaIndex 是首选框架之一。
L03

RAG 五步

RAG 拆成两个阶段：离线摄入（建知识库）+ 在线查询（回答问题）：

# 离线（建库，只做一次）：
读 Document → 切成 Node（小块）→ Embedding 向量化 → 存进 Index/VectorStore
# 在线（每次提问）：
问题 → Embedding → 检索最相似的 Node → 连同问题喂 LLM → 生成答案
读法："读→切→嵌→存"是离线建库（第 1-2 周），"检→答"是在线查询（第 3 周）。为什么要切块？因为大模型一次能读的内容有限，而且检索"小块"比"整篇文档"更精准。为什么要向量？因为向量能算"语义相似度"（下一天讲）。本课就按这五步逐层拆 LlamaIndex 的实现。
L04

core + integrations

仓库结构（llama_index/ 根）：

llama-index-core/          ★ 框架骨架（本课主角，抽象接口 + 默认实现）
llama-index-integrations/  300+ 集成（各种 LLM/向量库/Reader 的具体实现）
llama-index-instrumentation/  可观测
llama-index-utils/         工具
"核心 + 插件"的架构（又见） core 定义抽象接口（BaseLLM、BaseEmbedding、BaseVectorStore…）+ 一套能跑的默认实现；integrations 是各家的具体实现（OpenAI 的 LLM、Chroma 向量库、PDF Reader…）。你 pip install llama-index-core 得到骨架，再按需装集成（llama-index-llms-openai 等）。这和前面学的 APISIX（内核+插件）、Higress（core+集成）是同一思想——本课只读 core，把框架骨架吃透，集成用到时点名。

L06

5 行代码的 RAG

LlamaIndex 的经典"5 行入门"（体会它把 RAG 封装得多简洁）：

from llama_index.core import VectorStoreIndex, SimpleDirectoryReader
documents = SimpleDirectoryReader("data").load_data()      # 读数据（Day 03）
index = VectorStoreIndex.from_documents(documents)          # 切+嵌+存（Day 04-09）
query_engine = index.as_query_engine()                      # 建查询引擎（Day 12）
response = query_engine.query("这些文档讲了什么？")          # 检索+生成（Day 11-13）
print(response)
简单的背后是本课要拆的一切 这 5 行看着简单，但每一行背后都是一整套机制：load_data 是 Reader、from_documents 里藏着切块+嵌入+建索引+存储、as_query_engine 组装了检索器+合成器、query 跑完整的检索-生成链。本课就是把这 5 行"拆开揉碎"——学完你就知道每行下面发生了什么，也能替换其中任何一环。
L07

和 LangChain 对比

两大 LLM 应用框架的定位差异 LangChain：更通用的"LLM 编排框架"（链、Agent、各种集成），啥都能做但偏底层。LlamaIndex：专注"数据 + RAG"，在"把数据接入 LLM"这件事上更专业、抽象更贴合（Document/Node/Index/Retriever 一整套为 RAG 定制）。如果你的核心需求是"让 LLM 用我的数据"，LlamaIndex 更顺手；如果要复杂的通用编排，两者可结合。回想你学过的 langgraph（LangChain 生态的图编排）——LlamaIndex 的 Workflow（第 4 周）是它对标的能力。本课聚焦 LlamaIndex 的 RAG 强项。
