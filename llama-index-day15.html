LLM 抽象

第 3 周收官。RAG 最后一环——大模型本身。LlamaIndex 把各家 LLM 统一封装成一套接口，让 OpenAI/Claude/本地模型能互换。今天看 LLM 抽象、chat/complete、ChatMessage、流式，以及全局 Settings。

L01

为什么要抽象 LLM

各家 LLM 的 API 五花八门 OpenAI、Claude、Gemini、本地 Ollama……每家的 API 参数、返回格式都不同。如果你的 RAG 代码直接调 OpenAI，想换成 Claude 就要大改。LlamaIndex 定义统一的 LLM 接口——不管底层是谁，都用 llm.chat(messages) / llm.complete(prompt)。换模型只需换一行（换 integration），业务代码不动。回想前面所有组件（Reader/Embedding/VectorStore/Retriever）都是"接口统一、实现可换"——LLM 也不例外。这是 LlamaIndex（和所有好框架）的一贯设计。
L02

BaseLLM / LLM

base/llms/base.py 的 BaseLLM + llms/llm.py:163 的 LLM（更高层，加了 prompt 处理、query component 等）。核心抽象方法：chat、complete、stream_chat、stream_complete（+ 异步版 achat 等）。

读法：各家 LLM（llama-index-llms-openai 等 integration）继承 LLM，实现这几个方法。LlamaIndex 内部（合成器 Day 13、Agent Day 17）只调这套统一接口，不关心是哪家。还有 metadata（模型上下文窗口大小等，PromptHelper Day 13 用它算装箱）。
L03

chat vs complete

llm.complete("请续写：从前有座山")          # 文本补全（输入字符串，输出续写）
llm.chat([ChatMessage(role="user", content="你好")])  # 对话（输入消息列表，输出回复）
两种交互范式 complete（补全）：老式接口，给一段文本、续写。chat（对话）：现代接口，给一个"消息列表"（含 system/user/assistant 角色），返回下一条回复。现在的模型都是 chat 式（ChatGPT 那样）。LlamaIndex 两个都支持，内部会自动转换（chat 模型收到 complete 请求会包装成单条 user 消息）。RAG 合成答案时，通常用 chat（system 设定"你是问答助手"、user 放"资料+问题"）。
L04

ChatMessage / Role

base/llms/types.py：MessageRole（:53：SYSTEM/USER/ASSISTANT/TOOL/…）、ChatMessage（:1159：role + content，支持多模态内容块）、ChatResponse（:1282）、CompletionResponse（:1300）。

对话的"消息 + 角色"模型 一次对话是一串带角色的消息：SYSTEM（设定人设/规则）、USER（用户说的）、ASSISTANT（模型答的）、TOOL（工具返回的，Day 17 Agent 用）。ChatMessage 就是"一条消息 = 角色 + 内容"。新版 content 支持多模态（文本/图片块）。这套"消息-角色"模型是现代 LLM 应用的通用语言——Agent（Day 17）的多轮推理、记忆（Day 18）都基于它。
L05

流式

stream_chat / stream_complete 返回一个生成器，逐块产出 ChatResponse（每块含增量 delta）。llm.py:111 的 stream_chat_response_to_tokens 等辅助处理流。

流式 = 边生成边返回 LLM 生成是逐 token 的。流式接口让你"实时"拿到每个 token（delta），而不是等全部生成完。这样界面能"打字机效果"实时显示（Day 13 合成器的 streaming 就基于它）。统一的流式接口让所有下游（合成器、Agent、chat engine）都能支持流式，不管底层 LLM 是谁。
L06

Settings 全局

settings.py 的 Settings：全局默认配置——Settings.llm、Settings.embed_model、Settings.node_parser 等。不显式传时，各组件用 Settings 里的默认。

from llama_index.core import Settings
from llama_index.llms.openai import OpenAI
Settings.llm = OpenAI(model="gpt-4o")          # 全局设 LLM
Settings.embed_model = OpenAIEmbedding()        # 全局设嵌入
# 之后 VectorStoreIndex / query_engine 不传就用这些
一处设置，全局生效 不用每个组件都传 llm/embed_model——设一次 Settings.llm，所有组件默认用它。Day 01 的"5 行 RAG"能那么短，就是因为 Settings 提供了默认（或从环境变量读 OpenAI key）。换模型：改 Settings.llm 一行，全应用生效。（旧版叫 ServiceContext，已被 Settings 取代——更简洁的全局配置。）
L07

结构化与工具调用

LLM 还提供 structured_predict（让 LLM 返回 Pydantic 对象）和 predict_and_call / 工具调用能力（function_calling）——这是 Agent（Day 17）的基础。

读法：结构化输出：让 LLM 严格返回某个 schema 的 JSON（Day 13 提过）。工具调用（function calling）：LLM 决定"该调哪个函数、传什么参数"——这是 Agent 能"用工具"的底层能力。第 4 周的 Agent 就靠 LLM 的工具调用能力来自主决策。LlamaIndex 把各家 LLM 的工具调用也统一封装了。
