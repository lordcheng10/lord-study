Coze Loop 源码学习

20 天 · 每天 30 分钟 · 逐层读懂字节跳动开源的 AI Agent 开发运维（DevOps）平台 Coze Loop——Prompt 工程、评测（Evaluation）、可观测性（Observability）三大能力，全部从真实源码讲起。

00

开篇 · 这是个什么平台

Coze Loop 不是"搭 Agent 的地方"，而是"让 Agent 变得更好用、更靠谱"的工程化平台。如果说 Coze Studio 是"画布 + 搭建 Agent"的地方，Coze Loop 就是"给 Agent 做体检、调优、上线后持续监控"的地方——两者定位完全不同，经常被新人搞混。

🎯 一句话：Coze Loop 帮你把"写 Prompt / 跑评测 / 看 Trace 排障"这三件 AI 应用开发中最花时间的事，做成一套全生命周期管理的平台——从"随手改改 Prompt"到"上线后每一次调用都能追溯"。

它有三大核心能力，对应 6 个后端业务模块：

✍️

Prompt 开发

Prompt 的创建、版本管理、在线调试，边改边看模型真实反馈。

📊

Evaluation 评测

用数据集 + 评估器批量跑实验，量化"这版 Prompt/Agent 到底好不好"。

🔍

Observability 观测

基于 Trace 的全链路追踪，上线后每一次调用都能回放排查。

🧱

Foundation 地基

用户、空间、鉴权——所有业务模块的统一身份与权限底座。

零基础也别怕：前 5 天完全不假设你懂 DDD/Hertz/Kitex/Thrift。我们从"这是什么、怎么跑起来"讲起，一步步拆到路由、Handler、分层架构，再纵切一条完整业务链路，最后进入评测和观测这些更"平台特色"的能力。
01

6 模块架构总图（动起来看）

Coze Loop 后端遵循 DDD（领域驱动设计）分层，业务被拆成 6 个独立模块，外面统一套一层网关。下图那颗发光小球模拟"一次 HTTP 请求从网关落到具体业务模块"的路径：

网关层  ·  backend/api/（Hertz）
router_gen.goIDL 生成的路由
middlewareSession / Locale
handler.goHandler 桥接层
本地 Kitex 客户端进程内转发
业务模块层  ·  backend/modules/
prompt提示词开发
evaluation评测实验
data数据集
observabilityTrace 观测
地基模块  ·  foundation / llm
foundation用户/空间/鉴权
llm多模型协议适配
EinoLLM 调用框架
Wire依赖注入组装
基础设施  ·  infra/
MySQL业务数据
Redis缓存/限流
ClickHouseTrace 存储
MinIO / RocketMQ文件/消息

6 个业务模块各自的职责边界（后面 20 天会逐一拆开）：

prompt

Prompt 创建、版本、调试——Day 05/09/10 的主角。

evaluation

评测集、评估器、实验——Day 12/13 的主角。

data

数据集管理，评测的"原材料"——Day 11 的主角。

observability

Trace 全链路追踪与查询——Day 14 的主角。

foundation

用户/空间/鉴权，全平台地基——Day 08 的主角。

llm

基于 Eino 的多模型协议适配——Day 10 的主角。

为什么拆成 6 个模块？ 每个模块内部还会再分 application / domain / infra 三层（Day 06 细讲），模块之间不直接互调，而是通过"本地 Kitex 客户端"（Day 05）互相访问，这样每个模块可以独立开发、独立测试，边界清晰。
