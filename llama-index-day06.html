嵌入 Embeddings

第 2 周开始。RAG 的魔法核心是"嵌入"——把文本变成向量，让计算机能算"两段文本有多像"。今天讲透嵌入是什么、怎么算相似度、BaseEmbedding 的接口设计。这是"语义检索"的地基。

L01

什么是嵌入

嵌入 = 把文本变成一串数字（向量） 嵌入模型（embedding model）把一段文本变成一个高维向量（比如 1536 个数字）。神奇之处：意思相近的文本，向量也相近。"猫" 和 "小猫" 的向量很接近，"猫" 和 "汽车" 的向量很远。这样"找语义相似的文本"就变成了"找向量相近的向量"——变成纯数学问题（算向量距离），计算机很擅长。这是 RAG "语义检索"的地基：用户问"怎么退款"，即使文档里写的是"退货流程"，向量相近也能检索到。比关键词匹配强太多（关键词不同也能匹配语义）。
L02

语义相似度

向量距离 = 语义远近 两个向量有多"近"，常用余弦相似度（cosine similarity）衡量——算两个向量夹角的余弦值，范围 -1 到 1，越接近 1 越相似。还有点积、欧氏距离等。utils.py 里的 SimilarityMode 定义了这些模式（DEFAULT=余弦、DOT_PRODUCT、EUCLIDEAN）。检索时：把用户问题也嵌入成向量，然后算它和库里所有 Node 向量的相似度，取最相似的几个——这就是"向量检索"（Day 09）。
L03

BaseEmbedding

embeddings/ 里 BaseEmbedding（继承 TransformComponent，所以能进 ingestion 管道）的核心方法：

get_text_embedding(text) -> List[float]        # 单条文本 → 向量
get_text_embedding_batch(texts) -> List[...]    # 批量
get_query_embedding(query) -> List[float]       # 查询文本 → 向量
similarity(emb1, emb2, mode) -> float           # 算两个向量相似度
def __call__(nodes) -> nodes                     # 作为转换：给每个 Node 填 embedding
读法：作为 TransformComponent（Day 05），嵌入模型能直接进 ingestion 管道——__call__ 遍历 Node、给每个填 node.embedding（Day 02 的字段）。接口统一，所以 OpenAI/HuggingFace/本地各种嵌入模型都能互换。
L04

text vs query 嵌入

注意有 get_text_embedding（嵌入文档）和 get_query_embedding（嵌入查询）两个方法。

为什么文档和查询要分开？ 有些嵌入模型对"文档"和"查询"用不同的处理（比如加不同前缀 "search_document: " / "search_query: "）——因为"一段文档"和"一个问题"的语言风格不同，分开处理能让检索更准。大部分模型两者一样，但接口留了这个区分。建库时用 text 嵌入 Node，检索时用 query 嵌入问题——各走各的方法。这个细节直接影响检索质量。
L05

similarity 计算

embeddings/utils.py / indices/query 里的相似度函数（如 get_top_k_embeddings，Day 09 会用）：给一个查询向量和一堆候选向量，算相似度、排序、返回 top-k。

读法：核心就是"查询向量 vs N 个候选向量，各算 cosine，取最高的 k 个"。SimpleVectorStore（Day 09）的 query 就调这个。大规模时（百万向量）用专门的向量数据库（Faiss/HNSW）加速，但原理一样——找最近邻。
L06

批量与缓存

get_text_embedding_batch：一次嵌入多条（embed_batch_size 控制批大小）。嵌入模型多是调 API（OpenAI 等），批量能减少请求数。

嵌入是要花钱的（省着用） 调 OpenAI 嵌入 API 按 token 收费。建库嵌入几万个 Node = 不少钱。所以：① 批量调用（一次发多条，省请求开销）；② 缓存（Day 05 的 ingestion 缓存——没变的 Node 不重嵌）。这就是为什么 Day 05 的管道缓存那么重要——它省的主要就是嵌入费用。本地嵌入模型（HuggingFace）虽免费但慢/占资源——权衡。
L07

各家嵌入模型

core 只有 MockEmbedding（测试用）等；真实模型在 integrations：llama-index-embeddings-openai（text-embedding-3）、-huggingface（本地 BGE 等）、-cohere、-ollama…

选嵌入模型的考量 OpenAI text-embedding-3：效果好、要联网付费。BGE/GTE（HuggingFace 本地）：免费、数据不出本地、但要 GPU/慢。多语言场景选支持中文的模型（BGE-zh 等）。嵌入模型的选择直接影响检索质量——和你的语言、领域、预算都相关。换模型只需换一个 integration + 重新嵌入（因为不同模型的向量空间不通用，混用会乱）。
