create_react_agent

前三周你手搓了引擎。现在看官方预制：一行 create_react_agent 造一个完整 Agent。读 libs/prebuilt/chat_agent_executor.py——它是前三周所有零件的"成品样板"。

📍 你在整门课的位置
记忆·序列化→react_agent→ToolNode→流式
L01

一行造 Agent

from langgraph.prebuilt import create_react_agent

agent = create_react_agent(
    model="anthropic:claude-sonnet-4",
    tools=[search, calculator],           # 你的工具列表
)
agent.invoke({"messages": [("user", "北京天气如何，再算 3*7")]})
读法：create_react_agent（chat_agent_executor.py:278）返回一个已编译的 CompiledStateGraph——就是前 15 天讲的那种图，只不过结构是预置好的 ReAct 循环。拿到就能 invoke/stream，也能加 checkpointer/interrupt（前三周能力全部可用）。
📝 例子：最小可用的 Agent agent = create_react_agent(model, tools=[search]) —— 就这一行。传入一个模型、一份工具清单，返回的 agent 立刻就能 agent.invoke({"messages":[("user","北京天气?")]})。模型自己决定要不要调 search、调完拿结果接着答。你不用画任何节点和边。
L02

ReAct 回顾

ReAct = Reasoning + Acting 交替：LLM 思考 → 决定调工具 → 执行工具 → 拿结果再思考 → …… → 觉得够了就给最终答案。

ReAct 就是"边想边做"的循环 人解决复杂问题也是这样：想一下 → 查个资料 → 根据结果再想 → 再算一下 → …… → 得出结论。ReAct Agent 让 LLM 也这么干：模型不是一次性吐答案，而是可以说"我需要先查天气"→ 系统真的去查 → 把结果喂回给模型 → 模型接着想。循环直到模型不再要求调工具（它认为信息够了）。这是最主流的 Agent 范式，几乎所有框架（eino/crewAI/AutoGPT/OpenHands）核心都是它的变体。LangGraph 把它做成一张固定结构的图。
ReAct 就像生活中带一个实习生干活 你交代任务给实习生：他先想一下思路（Reasoning）→ 觉得缺资料就去查（Acting，调工具）→ 拿到资料回来接着想 → 可能再算一下 → 直到他觉得能交差了，把最终结果给你。模型就是这个实习生，图只负责"他想查资料就放他去查、查完喊他回来继续"。
🎵 四字口诀：想 → 调 → 看 → 再想（想思路→调工具→看结果→回炉再想），循环到不用再调工具为止。
L03

内部图结构

🤔 痛点：从零裸写一个 ReAct 图有多繁？ 手搓要：定义 AgentState、写 call_model 节点、绑定工具、写 should_continue 条件函数、连 START→agent→(条件)→tools→agent 一圈边、再 compile……十几行还容易漏。每做一个 Agent 都重抄一遍，烦。
💡 本质：官方把这套"标准 ReAct 图"封装成了一行 create_react_agent（chat_agent_executor.py:278）内部就是帮你搭好这张图并 compile：call_model 节点 + tools 节点 + should_continue 条件边组成的循环。它不是新魔法，就是你 Day 02-06 学的零件的"标准组装件"。
这就像生活中租房：裸写 StateGraph 是"毛坯房"——水电墙面全自己弄（自定义强但费劲）；create_react_agent 是"精装修拎包入住"——家具家电都配好，钥匙一拿就住。但精装房的每件家具（参数）你仍能换。
图：ReAct 循环 —— agent 想 → 要调工具就去 tools → 结果回填再想 → 不调了就 END

create_react_agent 内部就是构建这样一张 StateGraph（Day 02-04 的手法）：

# 简化示意
builder = StateGraph(AgentState)
builder.add_node("agent", call_model)      # LLM 思考节点
builder.add_node("tools", ToolNode(tools)) # 工具执行节点（Day 17）
builder.add_edge(START, "agent")
builder.add_conditional_edges("agent", should_continue)  # 要调工具→tools，否则→END
builder.add_edge("tools", "agent")         # 工具跑完回到 agent 继续想
return builder.compile(...)
读法：就是一个 agent ⇄ tools 的环 + 条件边决定"继续调工具还是结束"。这正是 Day 04 的条件边路由 + Day 06 的超步循环的组合。你完全能自己手搓出来——create_react_agent 只是帮你把这个常见结构封装好。

如果让你自己实现，最朴素的写法就是一个 while 循环：

# 极简版：不用图，纯 while 循环也能跑 ReAct
messages = [("user", question)]
while True:
    ai = model.bind_tools(tools).invoke(messages)   # 想
    messages.append(ai)
    if not ai.tool_calls:        # 不调工具了 → 交差
        break
    for call in ai.tool_calls:   # 调 + 看
        result = run_tool(call)
        messages.append(ToolMessage(result, tool_call_id=call["id"]))
# 再想（回到 while 开头）
💡 真实版比这个极简 while 多了什么？ 真实的 create_react_agent 把这个循环画成了图，多出的每一处都在解决 while 版的短板：
① 状态 schema（AgentState，chat_agent_executor.py:57）——用 add_messages reducer 规范"消息怎么追加"，而不是裸 list.append；
② should_continue（:831）当条件边——把 if not ai.tool_calls: break 变成图里可视化、可调试的路由；
③ tools 节点用 ToolNode——多个 tool_call 并行执行（while 版是串行 for）；
④ 接上检查点——while 版崩了就全丢，图版每超步存档、能续跑/时间旅行。
本质一样，图版把"可控、可观测、可持久"补齐了。
L04

agent 节点（call_model）

agent 节点把当前 messages（+可选 system prompt）喂给已绑定工具的模型，返回 AIMessage（可能含 tool_calls）：

model = model.bind_tools(tools)   # 告诉模型有哪些工具可用
response = model.invoke(state["messages"])
return {"messages": [response]}   # add_messages 追加（Day 03）
读法：bind_tools 把工具的 schema 塞进请求，模型才知道能调什么、参数长啥样。返回的 AIMessage 若带 tool_calls，说明模型想调工具；否则是最终回答。返回值走 add_messages 追加进历史。
L05

should_continue（路由）

条件边函数检查最后一条 AIMessage 有没有 tool_calls：

def should_continue(state):
    last = state["messages"][-1]
    if last.tool_calls:       # 模型要调工具
        return "tools"
    return END                # 没有 → 结束，返回最终答案
读法：这就是 ReAct 循环的"开关"：模型还想调工具就转去 tools 节点、否则结束。Day 17 讲的 tools_condition 就是这个函数的官方通用版。整个 ReAct 的"智能"其实在模型——图只负责"模型想调工具就让它调、调完再问模型"。

单步走查：问"北京天气如何，再算 3*7"，跟踪 messages 与 should_continue 的返回：

轮次 messages 最后一条 / 本轮新增 should_continue 返回
1 agentAIMessage(tool_calls=[天气(北京), 计算(3*7)])"tools"（有 tool_calls）
2 tools追加 2 条 ToolMessage："晴 28℃"、"21"（tools 节点固定回 agent）
3 agentAIMessage("北京晴 28℃，3*7=21")无 tool_callsEND（没有 tool_calls）
⚠️ 小白常误以为 "模型一次只能调一个工具"；其实一条 AIMessage 里可以带多个 tool_calls（上表第 1 轮同时开了"天气"和"计算"两张单），ToolNode 会并行执行——这也是 Day 17 的重点。
L06

参数一览

create_react_agent 常用参数（chat_agent_executor.py:278 起）：

  • model：字符串或 BaseChatModel。
  • tools：工具列表或 ToolNode。
  • prompt：system prompt（字符串/函数/可调用）。
  • checkpointer：加了它就有记忆（Day 12）。
  • store：长期记忆（Day 15）。
  • interrupt_before/after：加断点/人在环（Day 13-14）。
  • state_schema / response_format：自定义状态 / 结构化输出。
读法：前三周学的每一样能力，都是这里的一个参数。create_react_agent 是"把前三周零件组装好的成品"，但每个零件仍可通过参数替换/增强。
L07

站在零件之上

为什么先学引擎再学预制？很多人从 create_react_agent 入门，结果它一"不够用"就束手无策。你反过来：先懂了 StateGraph、通道、检查点、人在环，现在看 create_react_agent 一眼就穿——它不是魔法，是你已理解的零件的标准组装。需要定制时（换路由、加节点、改状态），你能直接下沉到 StateGraph 手搓，而不是被预制封装困住。这正是这门课把引擎放在应用前面讲的原因。
