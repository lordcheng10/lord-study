L01

痛点：为什么要学「workflow/nodes」

🤔 痛点 / 提问很多小白打开仓库就慌：文件太多、名字陌生、不知道今天该盯哪一块。
💡 本质今天的靶心是 packages/workflow/nodes。学完你应能用一句话说清它在整条链路里的位置。
大白话🍼 类比：前端节点组件 ↔ 后端 NodeType 一一对应。
🎯 阶段定位你在「前端 Rush 与 IDE」阶段（D67-D75）。前端是用户每天摸的面，要能对照后端概念。
L02

先建立坐标：它挂在哪一层

🤔 痛点 / 提问读源码第一问永远是：这个东西属于门卫、经理、专家，还是水电工？
💡 本质用 DDD 尺子量：api/ 收请求，application/ 编排用例，domain/ 写规则，infra/ 对接中间件，crossdomain/ 做部门间外交。
大白话把「层」记成楼层，把「域」记成房间号。今天的主角房间是：packages/workflow/nodes
发光点模拟一次请求从上到下穿过四层（并经 crossdomain 横向协作）
L03

真源码走读：关键入口怎么读

🤔 痛点 / 提问有了地图还不够，要练「打开文件第一眼看什么」。
💡 本质优先看：类型/接口定义 → 构造函数/New → 被谁调用 → 调用谁。Coze 里大量 interface + _impl.go 对：先读接口门牌，再进实现。
大白话接口像菜单，实现像厨房。菜单短好懂，厨房再乱也不慌。
packages/workflow/nodes今天的主坐标，先 ls / 打开文件头部看 package 与类型
接口 or 门面找 type Xxx interface / func New / func Init
调用方用 IDE / grep 找谁引用了它
被调方它依赖了哪些 crossdomain / infra

对照仓库路径阅读，行号以你本地版本为准；关注调用关系多于死记行号。

L04

动态理解：一次请求/一次执行怎么经过这里

🤔 痛点 / 提问静态目录脑中要动画起来：用户点「发送」之后，数据如何流过今天的模块。
💡 本质记住主链路：浏览器 → Hertz 中间件 → Handler → Application → Domain（可能经 Crossdomain）→ Infra/Eino → 流式回写。
大白话把发光小球想象成「用户的一句话」——看它经过哪些盒子。
页面点击 → TS API Client → Hertz API → Application → Domain → 流式回包 → chat-area 渲染
L05

设计取舍与边界坑

🤔 痛点 / 提问作者为什么这样写？哪些地方一改就炸？
💡 本质作者优先「边界清晰 + 可替换实现」：接口在 domain，脏细节进 infra/crossdomain。代价是文件更多，收益是改一处不易拖垮全局。
大白话好设计通常是在「解耦」和「省事」之间做交换。今天记住那个交换。
⚠️ 坑不要在 domain 里直接 new 基础设施客户端；不要绕过 crossdomain 去 import 别的 domain 内部包。
