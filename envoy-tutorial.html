00

开篇 · 这是个什么项目

Envoy 是 CNCF 毕业的云原生高性能边缘/服务代理（C++ 编写）。你可以把它理解成一个"超级智能的流量中转站"：所有进出你服务的网络请求都先经过它，它负责路由、负载均衡、限流、认证、可观测、故障注入等。它是 Istio 服务网格、Higress 网关的数据面（data plane）内核——学 Envoy 是理解现代云原生流量基础设施的地基。

🎯 一句话：Envoy = Listener（监听端口） + Filter Chain（过滤器链，L4/L7 处理逻辑） + Cluster（上游服务集群） + xDS（动态配置）。请求进 Listener → 走过滤器链 → HTTP 连接管理器 → 路由到 Cluster → 负载均衡选一个后端 → 转发。全程配置可通过 xDS 热更新、不重启。

🧵

线程模型

主线程 + N worker + 线程本地存储，热路径无锁，极致性能。

🔗

过滤器链

L4/L7 可插拔过滤器，请求处理像流水线一样组合。

🔄

xDS 动态配置

LDS/CDS/RDS/EDS 从管理服务器热更新，不重启。

🧩

Wasm 扩展

WebAssembly 插件（Higress 插件的运行基础）。

它在 higress-group 里的角色：Higress 是基于 Envoy + Istio 的云原生网关。Envoy 是"发动机"（数据面，真正转发流量），Istio 是"控制器"（控制面，下发配置），Higress 在其上做了增强和 Wasm 插件生态。本系列 5 个子项目层层相关，Envoy 是最底层的地基。前 5 天不假设你懂 C++/代理/网络编程。源码在 higress-group/envoy/source/。

Wasm扩展

Envoy 的心智模型是"Listener → 过滤器链 → Router → Cluster → 负载均衡 → 上游"——一个请求的旅程：

Listener收到连接→ L4/L7 过滤器逐层处理→ Router选 Cluster→ 负载均衡选后端转发
为什么 Envoy 这么快？ 三大法宝：①线程模型——主线程管配置、N 个 worker 线程各自处理连接，用"线程本地存储"避免锁竞争（热路径无锁）；②事件驱动——非阻塞 IO + 事件循环（Dispatcher），单线程扛海量连接；③零拷贝 Buffer——数据在内核和用户态间尽量不复制。这三点是第 1、4 周的重点。
