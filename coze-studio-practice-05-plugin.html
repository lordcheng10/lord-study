P05 · 插件：探索安装与自定义

上级：实战总目录。文件命名规范：coze-studio-practice-NN-slug.html。

0

前置与预期

现实预期：开源探索页插件数量与商业版差距大；许多官方插件点开后是「未授权」。本课重点是走通路径：浏览 → 安装/添加 → 鉴权意识 → 自定义 API 插件备选 → 挂到 Agent/工作流。
  • □ 已登录本地 Coze（P00）
  • □ 最好有一个 Agent（P02）或工作流（P01）可挂插件
1

打开探索页

  1. 侧栏点 探索，或直接访问 /explore
  2. 进入 插件 子页 /explore/plugin

图：探索页总览。

图：插件列表（实录页）。

2

安装 / 添加到空间

  1. 点开任一插件卡片（如飞书 / 搜索类）
  2. 按按钮「添加 / 安装到空间」（文案因版本略异）
  3. 回到 项目开发 → 智能体 → 技能 → 插件，应能选到刚添加的插件
若列表为空或只有模板：正常。开源默认插件产物在仓库 backend/conf/plugin/pluginproduct/（如 lark_*.yaml）。
3

完成鉴权（否则调用必挂）

鉴权类型你要准备什么
API Key / Token厂商控制台签发的密钥，粘贴到插件配置
OAuth按引导授权；本地需回调地址可达
无鉴权 HTTP适合自建演示 API（见下一步自定义）
踩坑：显示未授权仍硬测调试对话里只会「工具调用失败」。要么配好鉴权，要么改用自定义无鉴权接口 / P01 HTTP 节点。
4

自定义插件（可跟做的兜底）

作用：把你自己的 HTTP API 包装成工具，不依赖官方商店。
  1. 侧栏 资源库 → + 创建 → 选「插件」
  2. 填写插件名（如 httpbin_echo）
  3. 新建工具：Method POST，URL 可用 https://httpbin.org/post
  4. 参数定义一个 message（string）→ 保存 → 单工具调试
  5. 调试成功后，回到 Agent 技能区添加该插件
# 人设补充（可选）
当用户说「回声测试 xxx」时，调用 httpbin_echo，把 xxx 作为 message。
✅ 工具调试返回 200 且 body 含你的 message。
5

引用与验收

  • □ 探索页能打开插件列表
  • □ 至少完成：官方插件鉴权 或 自定义插件调试通 其一
  • □ Agent 技能区或工作流「插件节点」能选到该插件
  • □ 预览对话用明确指令触发一次调用
