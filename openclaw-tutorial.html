00

开篇 · 这是个什么项目

OpenClaw（🦞 口号"EXFOLIATE!"）是一个你自己部署、单用户的个人 AI 助理。它不是又一个聊天网站，而是一套连接你已有聊天渠道 + 一个智能体大脑 + 可扩展技能的系统：你在 Telegram/Slack/微信生态里发消息，它在后台想清楚、调工具、把答复送回同一个渠道。核心是 TypeScript 写的 monorepo，外加 macOS/iOS/Android 原生应用。

🎯 一句话：OpenClaw = Gateway（控制平面） + Channels（几十种聊天渠道接入） + Agent 大脑（LLM + 工具循环） + Skills/Extensions（技能与扩展） + Sandbox（安全执行）。消息从渠道进来 → Gateway 路由 → Agent 处理 → 答复从原渠道出去。

📮

多渠道接入

WhatsApp/Telegram/Slack/Discord/飞书/Signal/iMessage… 一套助理，处处可达。

🧠

Agent 大脑

LLM 抽象 + 模型故障转移 + 工具调用循环，想清楚再动手。

🧩

技能与扩展

skills/ 与 extensions/ 可插拔地给助理加本领。

🛡️

本地 + 安全

跑在你自己设备上，沙箱执行、防提示词注入、密钥管控。

和你学过的框架有何不同？eino/LangGraph/crewAI 是"给开发者的编排框架/库"；OpenClaw 是一个"给个人用的完整产品"——它把编排、渠道、部署、原生 App 全做好了。但你会发现底层依然是熟悉的东西：Agent 循环、工具系统、LLM 抽象、事件流。前 5 天不假设你懂 TypeScript monorepo/Gateway/渠道协议。源码在仓库根的 src/、skills/、extensions/、apps/。

OpenClaw 的心智模型是"渠道进 → Gateway 编排 → Agent 想+做 → 渠道出"——一条消息的循环：

渠道收到消息归一化→ Gateway路由到 Agent→ Agent调 LLM/工具→ 回复原路送回
为什么是"控制平面 + 渠道 + 大脑"这种结构？ 因为要在几十个不同聊天平台上提供"同一个助理"，就必须把"平台差异（渠道）"和"助理智能（大脑）"解耦，中间用一个统一的控制平面（Gateway）粘合。这和你学过的 OpenHands"事件流 + Runtime"、eino"组件 + 编排"是同一种分层解耦思想，只是 OpenClaw 面向的是"消费级个人助理产品"。
