一次 kickoff 的完整旅程

把 Agent + Task + Crew 串成一条完整故事线。今天跟着一次 kickoff()，看三个核心概念如何协同，数据如何在任务间流动。

📍 你在整门课的位置（第 1-2 周主线 · 昨天 Day 04 刚搭完 Crew 指挥中心，今天追一次真实 kickoff，明天 Day 06 拆两种 Process）
全景 D1· Agent·Task·Crew D2-4· kickoff 旅程 D5· Process D6· ReAct D7· 委派 D8· 规划·护栏 D9-10
L01

一段完整代码（我们要追踪它）

🤔 痛点：kickoff() 内部像个黑盒 你写完 crew.kickoff(inputs=...)，一行下去就拿到结果——但中间到底发生了什么？inputs 怎么钻进每个 Agent 的提示词？两个任务谁先谁后、上一个的产出怎么传给下一个？返回的 result 又究竟是谁的产出？今天就把这一行拆开看清楚。
from crewai import Agent, Task, Crew, Process

researcher = Agent(role="研究员", goal="研究 {topic}", backstory="...")
writer     = Agent(role="写手",   goal="写一篇关于 {topic} 的文章", backstory="...")

research = Task(description="研究 {topic}", expected_output="资料要点", agent=researcher)
write    = Task(description="写文章",       expected_output="800字文章",
                agent=writer, context=[research])   # ★ 依赖 research 的输出

crew = Crew(agents=[researcher, writer], tasks=[research, write],
            process=Process.sequential)
result = crew.kickoff(inputs={"topic": "多智能体"})   # ← 我们追踪这一行
读法：两个 Agent（研究员、写手）、两个 Task（研究、写作，写作依赖研究）、组成一个顺序执行的 Crew。下面逐步追踪 kickoff 内部发生了什么。
一次 kickoff 的完整旅程时序：橙=线性阶段，虚线框=任务循环（每个任务里跑一次 Agent ReAct），绿=最终汇总。标注为真实源码行号。
💡 一句话本质 kickoff() 不是"一个大函数干完所有事"，而是一条流水线：备料（插值）→ 按 Process 选执行策略 → 把任务列表逐个跑（每个任务里 Agent 各自跑 ReAct）→ 把最后一个任务的产出包成 CrewOutput 返回。今天做的，就是把这个黑盒拆成看得见的 6 步。
📝 例子：inputs 怎么一步步变成最终 result 调用：crew.kickoff(inputs={"topic": "多智能体"})
① 备料把所有 {topic} 占位符替换成 多智能体（role/goal/description 全部生效）
② research 任务先跑 → 产出"资料要点"
③ write 任务跑（context=[research]，拿到上一步资料）→ 产出 800 字文章
返回：result = 最后一个任务（write）的那篇文章；result.tasks_output 里还留着 research 的中间产物。
🏭 生活类比：kickoff 就像一条工厂流水线 把 inputs 想成一张订单（"要一篇多智能体的文章"）。kickoff 就是这张订单进厂后的旅程：先在备料台把图纸上的空格填好（插值 {topic}）→ 进第一道工序（研究员加工出半成品"资料要点"）→ 沿传送带进第二道工序（写手拿着这份半成品加工成成品"文章"）→ 最后质检打包出厂（包成 CrewOutput）。整条线一站接一站，上一站的产出就是下一站的原料——这就是本课要追踪的那趟旅程。
L02

① prepare 准备阶段

1
prepare_kickoff（crews/utils.py）：把 {topic} 用 inputs 插值成"多智能体"（Day 02 的 interpolate_inputs）。
2
若 crew.planning=True，先跑 _handle_crew_planning（Day 09）生成计划、追加进任务描述。
3
发 CrewKickoffStartedEvent（事件总线），设置 telemetry。
读法：正式执行前的"备料"——填占位符、（可选）规划、发开工事件。此刻 role/goal/description 里的 {topic} 都已变成实际内容。
L03

② 分发到流程

# crew.py:1021（Day 04 见过）
if self.process == Process.sequential:
    result = self._run_sequential_process()   # 我们的例子走这条
# _run_sequential_process (crew.py:1475) → self._execute_tasks(self.tasks)
读法：我们的 Crew 是 sequential，所以走 _run_sequential_process → _execute_tasks(tasks)——按顺序执行任务列表。（层级模式会先创建一个经理 agent，Day 06 讲。）
L04

③ 任务循环执行 _execute_tasks

_execute_tasks（crew.py:1519）遍历任务，对每个任务：

1
判断要不要跳过（条件任务 ConditionalTask，Day 03）。
2
_get_context(task, task_outputs)（crew.py:1826）：把前序任务输出拼成本任务的上下文（L06）。
3
task.execute_sync(...)（Day 03 的 _execute_core）执行任务。异步任务则攒进 futures 并发。
4
收集 TaskOutput，进入下一个任务。
读法：这就是"流水线"——research 任务先跑，输出攒起来；write 任务跑时，把 research 的输出作为上下文喂进去。顺序执行的精髓就在这个循环 + 上下文传递。
🎫 第一人称：假如你就是那张订单 "我是一张写着 {topic}=多智能体 的订单。我被推上流水线：备料台把我身上所有 {topic} 的空格填成'多智能体'；然后我进研究工位，研究员对着我埋头查资料、写出一份'资料要点'别在我身上；我继续往前走进写作工位，写手撕下我身上那份资料要点当参考，写出 800 字文章；最后我被送到打包台，只有'文章'被装箱出厂，那份中间的资料要点留在了台账里。"——这趟自述，就是 _execute_tasks 循环里逐个任务发生的事。
L05

④ 单个任务内：Agent 的 ReAct

每个 task.execute_sync 内部调 agent.execute_task（Day 02），Agent 进入 ReAct 循环（Day 07 精讲）：

1
Agent 把 role+goal+backstory+任务描述+上下文+记忆 拼成 prompt。
2
问 LLM → LLM 可能说"我要用搜索工具" → 执行工具 → 观察结果 → 再问 LLM。
3
循环直到 LLM 给出 Final Answer（或达到 max_iter）。
读法：研究员 Agent 拿到 research 任务，反复"思考→用工具查资料→看结果→再思考"，直到产出资料要点。这就是单个 Agent 执行任务时内部发生的事——Day 07 会逐行读 crew_agent_executor.py。
L06

⑤ 上下文链传递（关键时刻）

research 任务跑完，产出资料要点。轮到 write 任务时，因为它声明了 context=[research]：

# crew.py:1826 _get_context — write.context=[research]，非 NOT_SPECIFIED
# → aggregate_raw_outputs_from_tasks([research]) 把 research 的输出拼成字符串
# → 作为 context 传给 writer.execute_task(write, context="研究员产出的资料要点...")
这就是团队"协作"的实质 写手 Agent 拿到任务时，prompt 里包含了研究员刚产出的资料要点。于是它能基于研究成果写文章，而不是凭空写。"一个 Agent 的产出成为另一个 Agent 的输入"——这就是多智能体协作在代码层的真身。没有魔法，就是把上一个任务的 TaskOutput 拼进下一个任务的 prompt（Day 03 的上下文链三态在这里落地）。

👶 小白：研究员和写手是两个不同的 Agent，写手怎么就"知道"研究员查到了啥？它俩之间有心灵感应？

👨‍🏫 老师：没有心灵感应，全靠 Crew 这个项目经理手动传料。就像流水线上研究员把半成品放上传送带，Crew 把它取下来、原封不动贴进写手的任务说明书里。写手看到的"资料要点"，本质就是它这次提问时输入里多出来的一段文字。

👶 小白：那如果我忘了给 write 写 context=[research] 呢？

👨‍🏫 老师：顺序模式下默认就会把"前面所有任务"的产出串给它（Day 03 三态的默认档），所以一般不会漏。但如果你显式写成 context=[]（隔离），写手就真的两眼一抹黑，只能凭空编——传送带被你掐断了。

L07

⑥ 汇总输出

1
所有任务跑完，_create_crew_output(task_outputs)（crew.py:1880）取最后一个任务（write）的输出作为 crew 最终结果。
2
排空记忆写入、flush 事件总线、发 CrewKickoffCompletedEvent。
3
跑 after_kickoff 回调、算 token 用量，返回 CrewOutput。
读法：result 就是 write 任务的产出（那篇文章），中间的 research 输出保留在 result.tasks_output 里。print(result) 打印文章内容。旅程结束。
