开篇 · 这是个什么框架

Eino（读作 /'aino/）是字节跳动 CloudWeGo 团队开源的 Go 语言 LLM 应用开发框架。你可以把它理解成"Go 版的 LangChain + LangGraph"——但它遵循 Go 的工程习惯（强类型、显式、高性能）。

🎯 一句话：它帮你把"调大模型 / 用工具 / 检索 / 拼提示词"这些积木（组件），用图和链（编排）连起来，或直接搭成能自己调工具干活的 Agent——全程类型安全、原生支持流式。

它有四大支柱：

🧩

Components 组件

ChatModel / Tool / Retriever / ChatTemplate 等可复用积木（接口）。

🔗

Composition 编排

把组件连成 Chain / Graph / Workflow，能独立跑或暴露成 agent 工具。

🤖

ADK 智能体套件

搭带工具调用、多智能体协作、中断/恢复的 AI Agent。

📚

Examples 范例

常见模式与真实用例的可跑代码（独立仓 eino-examples）。

零基础也别怕：前 5 天完全不假设你懂 LLM/Agent/Go 泛型。我们从"大模型怎么调、消息长什么样"讲起，一步步搭到"图编排"和"多智能体"。不懂的名词先记住，后面一定展开。

Eino 的招牌设计是 Runnable 的 4 种流式范式——同一个组件，框架能在这四种调用方式间自动转换（Day 06 细讲）：

Invoke输入→输出
（非流→非流）
Stream输入→流
（非流→流）
Collect流→输出
（流→非流）
Transform流→流
（流→流）
为什么分层？ 底层 schema 定义"数据长什么样"，components 定义"能力有哪些接口"，compose 负责"把它们连起来跑"，adk 在最上面搭"会自己干活的 Agent"。每层只依赖它下面的层——这是清晰工程的经典分层。
