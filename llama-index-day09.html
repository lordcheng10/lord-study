Day 09 / 共 20 天 · 第 2 周 索引/嵌入/存储

向量存储 VectorStore

向量库是 RAG 检索的"引擎"。今天精读 SimpleVectorStore 的 add 和 query：向量怎么存、"给一个查询向量找最相似的 k 个"怎么算、metadata 过滤和 MMR 多样性检索。理解它，就理解了检索的底层。

L01

向量库的职责

vector_stores/types.py 的 BasePydanticVectorStore 核心方法：add(nodes)（存向量）、query(VectorStoreQuery)（相似度检索）、delete。

"存向量 + 找最近邻"两件事 向量库就干两件事：① add——把 Node 的向量存起来；② query——给一个查询向量，返回"最相似的 k 个 Node id + 相似度分数"。这就是"最近邻检索"（nearest neighbor search）。Day 06 讲的"意思近→向量近"在这里兑现：找最相似向量 = 找语义最相关的 Node。SimpleVectorStore 是默认实现（暴力算），生产用 Chroma/Qdrant 等（用 HNSW 等算法加速）。
L02

SimpleVectorStore

vector_stores/simple.py:64 class SimpleVectorStore(BasePydanticVectorStore)，数据存在 SimpleVectorStoreData（:48）里：

class SimpleVectorStoreData:
    embedding_dict: Dict[str, List[float]]   # node_id → 向量
    text_id_to_ref_doc_id: Dict[str, str]
    metadata_dict: Dict[str, Any]             # node_id → metadata（用于过滤）
读法：就是几个字典：embedding_dict（每个 Node 的向量）+ metadata_dict（每个 Node 的元数据，供过滤）。内存里的字典——简单直接，小规模够用。persist 时序列化成 JSON。
L03

add 存向量

simple.py:174 的 add(nodes)：遍历 Node，把 node.embedding 存进 embedding_dict[node.id_]、metadata 存进 metadata_dict。

读法：回收 Day 07——VectorStoreIndex 的 _add_nodes_to_index 就是调这个 add。Node 必须先有 embedding（Day 06 嵌入过）才能 add。专业向量库的 add 会把向量写进它的索引结构（HNSW 图等），SimpleVectorStore 只是塞进字典。
L04

query 检索

simple.py:244-305 的 query(VectorStoreQuery)：

def query(self, query: VectorStoreQuery, **kwargs) -> VectorStoreQueryResult:
    # 1. 按 metadata filters 和 node_ids 预过滤（缩小候选，L06）
    query_filter_fn = build_metadata_filter_fn(...)
    # 2. 收集通过过滤的候选向量
    for node_id, embedding in self.data.embedding_dict.items():
        if node_filter_fn(node_id) and query_filter_fn(node_id):
            node_ids.append(node_id); embeddings.append(embedding)
    # 3. 按 mode 算 top-k（DEFAULT/MMR/LEARNER）
    query_embedding = query.query_embedding
    if query.mode == MMR_MODE:
        top_similarities, top_ids = get_top_k_mmr_embeddings(...)     # 多样性（L07）
    elif query.mode == VectorStoreQueryMode.DEFAULT:
        top_similarities, top_ids = get_top_k_embeddings(query_embedding, embeddings,
            similarity_top_k=query.similarity_top_k, embedding_ids=node_ids)
三步：过滤 → 算相似度 → 取 top-k ① 先按 metadata/node_ids 缩小候选（比如"只在 2024 年的文档里找"）；② 对候选算查询向量和它们的相似度；③ 按 mode 取 top-k。VectorStoreQuery 装了查询向量、top_k、filters、mode。返回 VectorStoreQueryResult（node_ids + 相似度）。SimpleVectorStore 是"暴力法"——遍历所有向量算相似度（N 个就算 N 次）。小数据没问题，百万级才需要专业库的近似算法。
L05

top_k 相似度

get_top_k_embeddings（Day 06 提过）：查询向量对每个候选算 cosine 相似度，排序取最高的 similarity_top_k 个，返回 (相似度列表, node_id 列表)。

读法：similarity_top_k（默认 2）就是 Day 07 as_retriever(similarity_top_k=5) 传的——检索返回几个 Node。取太少可能漏掉相关内容，取太多引入噪声 + 塞爆 LLM 上下文。这个值是 RAG 调优的常见旋钮。返回的 node_id + score 会被包装成 NodeWithScore（Day 02）。
L06

metadata 过滤

simple.py:262 的 build_metadata_filter_fn：按 query.filters（如 {"year": 2024, "category": "finance"}）先过滤 Node，只在符合条件的里面算相似度。

"先过滤再检索"提升精度 纯语义检索有时不够——你想"只在财务类、2024 年的文档里找"。metadata 过滤让你先按结构化条件缩小范围（用 Day 02/03 存的 metadata），再在子集里做语义检索。比如问答机器人按用户权限过滤（只检索该用户能看的文档）。注意 SimpleVectorStore 若 persist 时没存 metadata，过滤会报错（:255-259）——所以 metadata 要一路带好。这是"混合检索"（结构化过滤 + 语义）的基础。
L07

MMR 多样性

simple.py:295 的 get_top_k_mmr_embeddings（MMR = Maximal Marginal Relevance）：不只选"最相似的",还兼顾"结果之间要不同"，用 mmr_threshold 平衡相关性和多样性。

避免检索出一堆"重复内容" 纯 top-k 可能返回 5 个几乎一样的段落（都在讲同一点）——浪费上下文、答案片面。MMR 在"相关"和"彼此不同"之间平衡：选相关的，但也避免选和已选内容太像的。这样 5 个 Node 覆盖更全面的信息。mmr_threshold 调平衡（偏相关 or 偏多样）。还有 LEARNER 模式（get_top_k_embeddings_learner，用 SVM 等学习式检索）。这些高级检索模式让 RAG 结果更好。
