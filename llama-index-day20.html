Day 20 / 共 20 天 · 第 4 周 Agent/Workflow/生态

部署与收官串讲

恭喜读完 LlamaIndex——也是整个源码学习系列的最后一站！今天讲部署、回顾四周主线、总结设计智慧、和你学过的其他框架对比，给这段学习画上圆满句号。

L01

core vs integrations

回顾 Day 01：llama-index-core（框架骨架 + 默认实现，本课主角）+ 300+ integrations（各家 LLM/嵌入/向量库/Reader 的具体实现）。

按需安装，组装你的 RAG 生产应用 = core + 你选的几个 integration。比如：llama-index-core + llama-index-llms-openai + llama-index-embeddings-openai + llama-index-vector-stores-qdrant + llama-index-readers-file。本课把 core（骨架和抽象接口）吃透了——换任何 integration 你都知道它实现的是哪个抽象、怎么接进流程。这就是"学框架骨架而非记 API"的价值：core 懂了，300 个集成一通百通。
L02

部署形态

  • 脚本/Notebook：原型验证（Simple* 内存后端，Day 08）。
  • API 服务：用 FastAPI 包成 HTTP 服务，向量库换 Qdrant/Chroma 等持久化后端。
  • llama_deploy / LlamaAgents：官方的 Workflow/Agent 部署方案（把 Workflow 部署成微服务）。
  • LlamaCloud / LlamaParse：官方托管平台（企业级解析/索引）。
读法：从 Notebook 原型到生产服务，主要变化是"换持久化后端 + 包成服务"——代码逻辑不变（回想 Day 08 的可插拔后端）。Workflow（Day 16）能用 llama_deploy 部署成独立可扩的服务。
L03

RAG 全链路回顾

# 离线建库（第 1-2 周）
Reader 读文档(Day3) → NodeParser 切块(Day4) → [IngestionPipeline(Day5)]
  → Embedding 向量化(Day6) → VectorStoreIndex(Day7) 存进 StorageContext 三件套(Day8-9)

Workflow(Day16) 编排 → Agent(Day17) 用工具 → ChatEngine 多轮(Day18) → 观测评估(Day19)
这条链贯穿全课——你现在能看穿 Day 01 那"5 行 RAG"背后的每一步。
L04

四周主线

W1 RAG 全景与摄入：RAG 五步 → Node 数据结构 → Reader → 切块 → Ingestion 管道
W2 索引/嵌入/存储：嵌入(语义向量) → VectorStoreIndex → StorageContext 三件套 → 向量检索 → 其他索引
W3 检索与查询：Retriever → QueryEngine → 响应合成 → 后处理/提示词 → LLM 抽象
W4 Agent/Workflow/生态：Workflow 事件驱动 → Agent 工具循环 → 聊天记忆 → 可观测评估
L05

设计智慧

  1. 一切皆 Node + 统一 TransformComponent：数据用 Node 表达，处理步骤（切块/嵌入/抽取）都是"输入 Node、输出 Node"的转换，可任意组合成管道。
  2. 接口统一、实现可换：Reader/Embedding/VectorStore/Retriever/LLM 都是抽象接口 + 多实现——换后端只换一行。
  3. 两阶段思想：离线建库 + 在线查询分离；粗检索 + 精排（rerank）分离。
  4. 版本化缓存：ingestion 缓存、合成缓存——用内容 hash 做键，省嵌入/LLM 钱。
  5. Workflow 事件驱动：把复杂控制流（Agent 的多步循环）表达成事件流。
这些和你学过的项目一脉相承 "统一接口 + 可插拔实现"你在 APISIX/Higress/wasm-go 都见过；"两阶段/缓存"是通用工程智慧；"事件驱动/图编排"和 langgraph 呼应。看完这么多项目，你会发现好框架的设计原则是相通的——抽象出稳定接口、把变化关进插件、用缓存换性能、用统一数据模型串联流程。

和其他框架对比

框架定位你学过的关系
LlamaIndex数据 + RAG 专精，Agent 用 Workflow本课
LangChain通用 LLM 编排，全Day 01 对比过

框架多，核心概念相通 不管哪个框架，核心都是那几样：数据接入、检索、LLM 调用、多步编排、Agent、记忆、可观测。名字不同、API 不同，但概念一致。你学了这么多（eino/OpenHands/crewAI/AutoGPT/SuperAGI/langgraph/openclaw + LlamaIndex），已经建立了"跨框架的心智模型"——看新框架能快速映射到已知概念。这比记住某个框架的 API 值钱得多。
L07

RAG 调优清单

RAG 效果不好时，按这个顺序排查（对应本课各天）：

  1. 切块（Day 4）：chunk_size/overlap 合不合适？切碎了语义？
  2. 嵌入模型（Day 6）：适合你的语言/领域吗？
  3. 检索（Day 9/11）：top_k 够吗？要不要混合检索/rerank（Day 14）？
  4. 提示词（Day 14）：QA 提示引导对了吗？加"没有就说不知道"？
  5. 合成模式（Day 13）：compact/tree_summarize 选对了？
  6. 用评估验证（Day 19）：分段测检索/生成，定位到底哪弱。
读法：经验：检索质量 > 提示词 > 合成/模型——先保证"检索到对的内容"（切块+嵌入+检索+rerank），再优化"怎么用内容答"（提示词+合成）。用评估（Day 19）客观验证每次改动。
