Higress Console 源码学习

00

开篇 · 这是个什么项目

Higress Console 是 Higress（上一站的 AI 网关）的Web 管理控制台——一个全栈应用：Java Spring Boot 后端 + React/TypeScript 前端。用户在浏览器界面上点点点管理路由、服务源、域名、证书、Wasm 插件、AI 供应商、消费者，控制台把这些操作翻译成 Higress 认识的配置（K8s Ingress + higress.io/* 注解 + CRD），写进 K8s。

🎯 一句话：Console = React 前端（管理界面） + Spring Boot 后端（REST API） + SDK（配置抽象） + K8s 客户端（读写 Ingress/CRD/ConfigMap/Secret）。你在界面操作 → 前端调后端 REST → Service 处理 → SDK 写 K8s CRD → Higress 控制器（上一站）读到并生效。

🖥️

React 前端

ice.js + antd 管理界面，动态渲染插件配置表单。

☕

Spring Boot 后端

REST API + Service 分层，274 个 Java 文件。

🔌

SDK + K8s 客户端

配置抽象 + 读写 Ingress/CRD/ConfigMap。

🤖

AI 供应商管理

配置 LLM provider、插件、消费者。

与上一站的关系（承上）：上一站 Higress 是"控制器/数据面"（读配置生效流量）；Console 是"给人用的管理界面"——它生成那些 Higress 配置（Ingress + 注解）。你在 Console 建一条路由，最终变成 Higress 控制器（上一站 Day 04）翻译的那个 Ingress。建议先学完 Higress。源码在 higress-console/backend/（Java）+ frontend/（React）。

架构全景（动起来看）

下图那颗发光小球是"用户在界面操作 → 变成 Higress 配置"的旅程。从上到下：前端 → 后端 API → SDK → K8s。

页面路由/插件/AI
动态表单插件配置
API 层axios

Service业务逻辑

存储抽象K8s/单机

Ingress路由

ConfigMap/Secret

Console 的心智模型是"界面操作 → REST API → SDK → K8s 配置 →（Higress 控制器读到）"：

界面点击建路由→ 后端 Service处理→ SDK写 Ingress+注解→ Higress 控制器读到生效
Console 和 Higress 控制器怎么协作？ Console 不直接控制 Envoy——它只是把用户操作写成 K8s 里的 Ingress/CRD/ConfigMap。然后上一站的 Higress 控制器 watch 到这些资源，翻译成 Istio 配置喂 istiod、生成 xDS 给 Envoy。Console 是"人机接口"，Higress 控制器是"配置引擎"——通过 K8s 资源解耦。
