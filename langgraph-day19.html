Day 19 / 共 20 天 · 第 4 周 应用层

部署与 Platform

本地跑通的图怎么变成线上服务？langgraph-cli + langgraph.json + LangGraph Server/Platform 把你的图包装成带 API、持久化、任务队列的生产服务。

L01

从图到服务

你的图现在是个 Python 对象。要给别人用，得变成能收 HTTP 请求、多用户并发、状态持久、长任务可靠的服务。LangGraph Platform 就是干这个的——把生产级基础设施封装好。

"能跑" ≠ "能上线" 本地 graph.invoke() 能跑，但上线要面对一堆现实问题：多个用户同时请求怎么办？长任务跑一半服务重启了怎么办？怎么给前端一个稳定 API？怎么管理不同配置的 Agent？这些"脏活累活"就是 LangGraph Platform 替你解决的。它把你前三周学的检查点、流式、人在环，包装成一个开箱即用的生产服务器。你负责写图逻辑，它负责把逻辑变成靠谱的线上服务。
L02

langgraph.json（部署清单）

部署配置文件，声明"哪些图要暴露、依赖、环境变量":

{
  "dependencies": ["."],
  "graphs": {
    "my_agent": "./agent.py:graph"    // 图名 → 文件里的图对象
  },
  "env": ".env"
}
读法：graphs 把"图名字"映射到"哪个文件的哪个变量"——服务启动时按这个清单加载图、暴露成 API。一个服务可托管多张图。这是"约定优于配置"的部署入口。
L03

langgraph-cli

pip install langgraph-cli
langgraph dev      # 本地起开发服务器（含 LangGraph Studio 可视化调试）
langgraph build    # 打包成 Docker 镜像
langgraph up       # 本地起完整服务（含 Postgres + Redis）
读法：langgraph dev 是开发利器——起本地服务 + 可视化 Studio，能看图结构、单步调试、时间旅行（Day 13）。build/up 走向生产（Docker）。CLI 把"部署"简化成几条命令。
L04

Server 提供什么

LangGraph Server 在你的图之上，自动提供一套生产能力：

  • REST API：invoke/stream 变成 HTTP 端点。
  • 持久化：内置 Postgres 做 checkpointer + store（Day 12/15）。
  • 任务队列：长任务后台跑，Redis 做队列（L06）。
  • 多租户：thread/assistant 管理（Day 12 thread_id 的生产版）。
读法：你前三周手动配的 checkpointer/store，Server 全帮你接好（Postgres）。你只管写图。这是"框架把工程复杂度吃掉"的又一体现。
L05

Assistants 与 Runs

概念含义
Assistant图 + 一套配置（prompt/model/参数）的组合——同一张图配不同参数=不同 assistant
Thread一个会话（Day 12 的 thread_id，这里是一等公民）
Run一次执行（在某 thread 上跑某 assistant）
同一张图，多个"人设" Assistant = 图 + 配置。比如同一个客服图，配"温柔话术 + GPT-4"是一个 assistant，配"简洁话术 + Claude"是另一个——图代码不变，只是配置不同。这让你不改代码就能派生出多个 Agent 变体，还能各自版本管理。Thread 是会话、Run 是一次跑——三个概念把"谁、在哪个会话、跑哪个 Agent 版本"讲清楚了。
L06

任务队列（长任务可靠）

Agent 任务常常几十秒到几分钟。Server 用任务队列把 Run 放后台执行：客户端发起后立即拿到 run_id，之后轮询/流式获取进度；服务重启也能靠检查点续跑（Day 11）。

读法：长任务不阻塞 HTTP 连接——发起即返回，后台队列消费，配合检查点做到"可靠长运行"。这正是 Day 11 持久执行能力在生产架构里的价值兑现：队列 + 检查点 = 崩了能续、慢了不卡。
L07

SDK 客户端

from langgraph_sdk import get_client
client = get_client(url="http://localhost:2024")

thread = await client.threads.create()
async for chunk in client.runs.stream(thread["thread_id"], "my_agent",
                                      input={"messages": [...]}):
    print(chunk)   # 远程流式，和本地 graph.stream 体验一致
读法：SDK 让远程调用和本地 API 几乎一样（stream/invoke/get_state 都有对应）。前端/其他服务通过它接入你部署的 Agent。本地 graph.stream 学到的一切，在远程 client.runs.stream 无缝复用。
