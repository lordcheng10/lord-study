Day 14 / 共 20 天 · 第 3 周 检索与查询

后处理与提示词

检索到的 Node 在喂给 LLM 前，常要"精修"——过滤噪声、重排、补充上下文。今天看 postprocessor（后处理器）和 prompts（提示词模板系统）。它们是提升 RAG 质量的两个关键杠杆。

L01

后处理的位置

回想 Day 12：QueryEngine 的 retrieve = 检索器检索 + _apply_node_postprocessors。后处理夹在"检索"和"合成"之间。

"检索给一堆候选，后处理精挑细选" 检索器返回 top-k（比如 10 个），但这 10 个未必都好——可能有些相关度低、有些重复、有些需要补上下文。后处理器在合成前"精修"这批 Node：过滤掉差的、重新排序、补充相邻块。好比初筛出 10 份简历，HR 再精挑 3 份。后处理是"两阶段检索"（粗检索 + 精排）的精排阶段——对 RAG 质量提升显著。
L02

BaseNodePostprocessor

postprocessor/ 的 BaseNodePostprocessor：核心方法 postprocess_nodes(nodes, query_bundle) -> List[NodeWithScore]——输入一批带分数的 Node，输出精修后的。

读法：又是"输入 Node 列表、输出 Node 列表"的统一接口——所以多个后处理器能串成链（QueryEngine 的 node_postprocessors 列表，依次应用）。可以先过滤、再重排、再取窗口——像流水线。
L03

相似度过滤

postprocessor/ 的 SimilarityPostprocessor：按 similarity_cutoff 过滤——只保留相似度分数高于阈值的 Node。

"宁缺毋滥"，扔掉弱相关 检索的 top-k 是"最相似的 k 个",但如果库里根本没有相关内容，这 k 个可能都是"矮子里拔将军"（分数很低）。把它们喂给 LLM 反而误导（让它基于无关内容瞎答）。SimilarityPostprocessor 设个阈值（如 0.7），低于的直接扔——宁可少给几个，也不给无关的。这能减少幻觉。如果全被过滤掉，说明"知识库里没答案",比硬答强。
L04

rerank 重排

重排类后处理器（如 LLMRerank、integration 里的 CohereRerank/SentenceTransformerRerank）：用一个更强的模型重新给候选打分排序。

"两阶段检索"的精排（RAG 提效神器） 向量检索快但不够准（只看向量相似）。rerank 用专门的"重排模型"（cross-encoder）或 LLM，把"查询 + 每个候选"一起看、给出更准的相关度分，重新排序。流程：向量粗检索取 top-20（快、召回全）→ rerank 精排取 top-5（准）。这是提升 RAG 准确率最有效的技巧之一——粗检索保召回、rerank 保精度。代价是 rerank 要额外调模型（慢/花钱），但值得。
L05

上下文窗口

MetadataReplacementPostProcessor / PrevNextNodePostprocessor：配合 Day 04 的 SentenceWindow / Day 02 的 PREV/NEXT 关系，把命中的小块"扩展"成带上下文的内容。

"命中一句，给出一段" SentenceWindow 检索（Day 04）：用单句嵌入检索（精准命中），但单句给 LLM 上下文不够。MetadataReplacementPostProcessor 在检索命中后，把 Node 内容替换成它 metadata 里存的"前后窗口"（周围几句）——检索用小粒度（准），给 LLM 用大粒度（全）。PrevNextNodePostprocessor 则用 PREV/NEXT 关系取相邻块。这解决了"检索精度"和"上下文完整"的矛盾——回收 Day 02/04 的伏笔。
L06

prompts 模板

prompts/：PromptTemplate（字符串模板 + 变量）、ChatPromptTemplate（多轮消息模板）。RAG 的核心提示词如 DEFAULT_TEXT_QA_PROMPT_TMPL（"根据以下上下文回答问题：{context_str}\n问题：{query_str}"）。

提示词是 RAG 的"说明书" LLM 怎么用检索到的内容答题，全看提示词怎么写。默认的 QA 提示词类似"这是相关资料：{context}。请只根据资料回答：{question}"——引导 LLM"基于资料、别乱编"。PromptTemplate 用 {变量} 占位，运行时填入检索内容和问题。调 RAG 效果时，改提示词（比如加"如果资料里没有就说不知道"）常有奇效——比换模型便宜。refine 模式（Day 13）还有专门的"精炼提示词"。
L07

PromptMixin

prompts/mixin.py 的 PromptMixin：让组件（检索器/合成器/查询引擎）能"暴露和替换"自己用的提示词——get_prompts() / update_prompts()。

读法：回想 Day 11 BaseRetriever(PromptMixin, ...)——很多组件都 mix 了它。好处：你能一行 query_engine.update_prompts({...}) 换掉深层组件的提示词，不用改源码。比如把默认英文提示词换成中文、加约束。这让"提示词工程"可以在应用层灵活做，不必动框架。提示词是 RAG 最易调、最见效的地方。
