Day 18 / 共 20 天 · 第 4 周 Agent/Workflow/生态

聊天引擎与记忆

QueryEngine 是"单轮问答"，但真实对话是多轮的（"它多少钱?" 这个"它"指上文提过的东西）。今天看 ChatEngine（多轮对话）和 Memory（管理对话历史）——让 RAG/Agent 记住上下文。

L01

单轮 vs 多轮

多轮对话的"指代"难题 QueryEngine 每次 query 是独立的（Day 12）——它不记得上一句。但对话有上下文："公司的退款政策是什么?"→"那需要多久?"——第二句的"那"指退款。如果不记历史，检索"那需要多久"根本检索不到东西。ChatEngine 解决多轮：它维护对话历史，把当前问题结合历史处理（比如把"那需要多久"改写成"退款需要多久"再检索）。这是从"问答"到"对话"的关键升级。
L02

ChatEngine 模式

chat_engine/：simple.py（纯聊天，无 RAG）、condense_question.py、context.py、condense_plus_context.py（默认推荐）。index.as_chat_engine(chat_mode=...) 创建。

读法：不同模式 = 不同的"结合历史 + RAG"策略。SimpleChatEngine：只聊天不检索。CondenseQuestion：把历史+新问题浓缩成一个独立问题再检索。Context：每轮都检索、把结果塞进 system 提示。CondensePlusContext：两者结合（默认）。
L03

condense_question 模式

chat_engine/condense_question.py：先用 LLM 把"对话历史 + 当前问题"浓缩成一个"独立问题"，再拿它走 RAG。

"改写问题"解决指代 历史："退款政策是什么?" → 答。当前："那需要多久?"。CondenseQuestion 先让 LLM 看历史，把"那需要多久"改写成"退款需要多久"（独立、无指代），再用这个改写后的问题检索。这样检索能命中"退款时长"的内容。优点：检索的问题总是完整独立的。缺点：多一次 LLM 调用（改写）。适合"每轮都需要检索"的知识问答。
L04

context 模式

chat_engine/context.py：每轮用当前消息检索相关 Node，把它们塞进 system 提示，连同完整对话历史一起给 LLM。

"带着资料聊天" Context 模式不改写问题——它每轮检索相关资料，作为"背景知识"放进 system 提示，然后 LLM 看着"资料 + 完整对话历史"回答。好处：保留完整对话上下文（LLM 自己理解指代）、资料实时相关。CondensePlusContext（默认）= 先浓缩问题做精准检索 + 保留对话上下文——兼顾两者优点。选哪个模式取决于你的对话特点。
L05

Memory 记忆

memory/：memory.py（新版统一 Memory）、chat_memory_buffer.py、chat_summary_memory_buffer.py、vector_memory.py、simple_composable_memory.py + memory_blocks/。存对话历史（ChatMessage 列表，Day 15）。

Memory = 对话历史的管理者 Memory 存这次对话的所有消息（user/assistant 轮流）。ChatEngine/Agent 每轮从 Memory 取历史、处理完把新消息写回。核心难题：对话越长历史越长，塞不下 LLM 上下文——所以有不同的 Memory 策略管理"记多少、怎么记"（下面）。回想你学过的其他框架的 memory（SuperAGI 的滚动记忆压缩、crewAI 的统一记忆）——同一个问题的不同解法。
L06

缓冲区 token 限制

memory/chat_memory_buffer.py 的 ChatMemoryBuffer：保留最近的消息，用 token_limit 控制——超了就丢最老的。

最简单：只记最近的 ChatMemoryBuffer 像"滑动窗口"——只保留最近 N token 的对话，老的丢弃。简单有效，适合大多数场景（远古对话通常不重要）。缺点：丢掉的历史彻底忘了（如果用户 10 轮前说的名字，现在问就想不起）。这是"记忆容量"和"上下文限制"的最朴素折中。
L07

摘要与向量记忆

  • ChatSummaryMemoryBuffer：历史超限时，用 LLM 把旧对话摘要成一段，保留摘要 + 最近消息——不彻底忘，压缩记忆。
  • VectorMemory：把历史消息也向量化存起来，需要时检索相关历史（而非全带）——"长期记忆"。
  • SimpleComposableMemory / memory_blocks：组合多种记忆（短期缓冲 + 长期向量 + 事实块）。
三层记忆策略，越来越像人 Buffer（只记最近）→ Summary（压缩旧的成摘要）→ Vector（旧对话存起来、按需检索）。越往后越像人的记忆——近的记得清、远的记要点、需要时能"回忆"。新版 Memory（memory.py + memory_blocks/）支持"可组合记忆块"——短期 + 长期 + 静态事实混合，这是当前 Agent 记忆的前沿。选哪种看你的对话长度和"要不要记住远期信息"。
