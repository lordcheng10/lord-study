LangGraph 零基础入门

框架最底层的 L1 就是 LangGraph。搞懂它的 6 个抽象，你就懂了"一个 Agent 内部怎么一步步跑"。配 4 个不配 key 也能跑的最小 demo。

L01

为什么用"图"来跑 Agent

一个稍微复杂的 Agent 不是"调一次大模型就完事"，它有很多步骤：先分诊、再并行取证、再综合、再质检、质检不过还要打回重做……这些步骤有先后、有分支、有循环。

LangGraph 的思路：把这些步骤画成一张"流程图"（graph）来跑。 图里每个方框是一个"节点（Node）"= 一个步骤；方框之间的箭头是"边（Edge）"= 执行顺序。所有节点共享一块叫 "State" 的黑板来传数据。

下面这张图会自己动起来——小球式的高亮会依次点亮每个节点，模拟一次真实执行（这正是 Day 14 要精读的 sre-rca Agent 的简化版）：

START→ triage分诊→ 取证并行专家→ synthesizer综合→ critic质检→ writeback沉淀→ END
为什么不直接写 if/else 一路调下来？ 因为"图"这种结构天生支持并行（4 个专家同时跑）、循环（质检不过打回重做）、断点续跑（跑一半崩了能接着跑）、还能自动画出拓扑图。这些用裸 if/else 写会非常痛苦。
L02

六大核心抽象

LangGraph 你只要先掌握这 6 个概念，就够读懂本框架 90% 的图代码了：

📋

State 状态

全图共享的"黑板"，通常是一个带类型的字典（TypedDict）。

⬜

Node 节点

一个处理步骤，本质是个函数：读 state，返回要写回 state 的部分。

➡️

Edge 边

节点间的箭头，决定执行顺序。有普通边和条件边两种。

🔀

Conditional Edge

条件边：根据 state 的值决定下一步走哪个节点（分支/循环）。

➕

Reducer 归约器

多个节点同时写同一个字段时，"怎么合并"的规则（覆盖 or 累加）。

💾

Checkpointer

存档器：把每一步的 state 存下来，支持中断恢复、多会话隔离。

仓库里 docs/learn-langgraph/ 提供了 4 个能直接跑的最小 demo（默认用 MockLLM，不配 key 也能跑）。下面 4 讲就一个个过。

L03

State：全图共享的黑板

State 通常定义成一个 TypedDict（带类型标注的字典）。每个节点从它读输入、返回一个"部分字典"合并回去。

from typing import TypedDict

class MyState(TypedDict, total=False):
    question: str        # 输入
    answer: str          # 某个节点写的输出
    step_count: int
TypedDict = "带类型标注的字典"。用起来就是普通 dict，但 IDE/类型检查能帮你catch 拼错的 key。
total=False = "所有字段都可选"。因为每个节点只填自己产出的那几个字段，不用一次性填满。

节点函数的约定非常简单——接收整个 state，返回一个只包含"我改了哪些字段"的 dict，LangGraph 自动帮你合并回全局 state：

def answer_node(state: MyState) -> dict:
    q = state["question"]
    return {"answer": f"你问的是：{q}"}   # 只返回改动的字段
L04

Node 与 Edge — demo1：串一条线

对应 docs/learn-langgraph/01_state_node_edge.py。把 3 个节点用普通边串成一条直线：

from langgraph.graph import StateGraph, START, END

builder = StateGraph(MyState)          # 1. 以 State 类型建图
builder.add_node("a", node_a)          # 2. 注册节点
builder.add_node("b", node_b)
builder.add_node("c", node_c)
builder.add_edge(START, "a")           # 3. 连边：START→a→b→c→END
builder.add_edge("a", "b")
builder.add_edge("b", "c")
builder.add_edge("c", END)
graph = builder.compile()              # 4. 编译成可执行图

result = graph.invoke({"question": "hi"})   # 5. 跑！传入初始 state
START→ node_a→ node_b→ node_c→ END

START 和 END 是两个特殊的内置节点，代表图的入口和出口。invoke() 从 START 开始，沿边一路执行到 END，返回最终的 state。

L05

条件边 — demo2：三态分支

对应 docs/learn-langgraph/02_conditional_edge.py。条件边让图能根据 state 的值"走不同的路"。这正是本框架里 Critic 质检的核心模式——PASS / FAIL 重试 / 触顶结束三态：

critic
质检结果?
通过 → writeback（沉淀经验，结束）
不过 & 没超次数 → 回 synthesizer 重做
不过 & 超了 2 次 → END（诚实说"信息不足"）
def route(state) -> str:               # 路由函数：返回下一个节点的名字
    if state["passed"]:
        return "writeback"
    if state["retry_count"] >= 2:
        return "END"
    return "synthesizer"

builder.add_conditional_edges("critic", route, {
    "writeback": "writeback",
    "synthesizer": "synthesizer",     # ← 指回前面的节点 = 形成循环
    "END": END,
})
划重点：条件边指回一个更早的节点，就形成了循环（retry loop）。用 retry_count 计数 + 上限判断，防止无限循环。本框架把这个模式封装成了 toolkit 里的 build_critic_router()，业务不用手写——Day 07 会看到。
L06

Reducer + 并行 — demo3：扇出扇入

对应 docs/learn-langgraph/03_reducer_parallel.py。当多个节点从同一个上游出发、又都指向同一个下游时，LangGraph 自动并行执行它们：

recall
召回 ⇉
trace 专家metric 专家deploy 专家log 专家
⇉ rag
汇合

问题：4 个专家同时往 state 写东西，如果它们写同一个字段会打架。解决办法就是 Reducer（归约器）——用 Annotated 告诉 LangGraph"这个字段多方写入时怎么合并"：

from typing import Annotated
import operator

class State(TypedDict, total=False):
    # 各专家写各自的字段 → 天然不冲突，默认"覆盖"即可
    trace_finding: dict
    metric_finding: dict
    # 多个节点都要 +1 的计数器 → 用 operator.add 做"累加"归约
    retry_count: Annotated[int, operator.add]
Reducer 到底是什么？ 就是一个函数 (旧值, 新值) → 合并后的值。默认是"新值覆盖旧值"；写 Annotated[int, operator.add] 就是"两个值相加"。比如两个节点各返回 {"retry_count": 1}，累加后 state 里就是 2——避免了并发写覆盖导致计数丢失。

本框架的 sre-rca Agent 里，4 个专家字段各自独立（覆盖语义），而 retry_count 用累加语义（state.py:48），正是这个设计。

L07

Checkpointer — demo4：存档与恢复

对应 docs/learn-langgraph/04_checkpointer.py。Checkpointer（存档器）把每跑完一个节点的 state 存下来。带来两个能力：

  • 断点续跑：图跑到一半崩了/被中断，重新用同一个 thread_id 调用，能从断点接着跑，不用从头来。
  • 多会话隔离：不同的 thread_id 各有各的 state，互不干扰——一个 agent 服务能同时处理很多用户的对话。
from langgraph.checkpoint.memory import MemorySaver

graph = builder.compile(checkpointer=MemorySaver())   # 挂上存档器

# thread_id 决定"这是哪一次会话"
config = {"configurable": {"thread_id": "user-42"}}
graph.invoke({"question": "第一问"}, config)
graph.invoke({"question": "追问"}, config)   # 同一 thread，能看到上一步的 state
thread_id 就像"会话 ID"。同一个 thread_id 的多次调用共享同一份存档；换个 thread_id 就是全新一份。

本框架把存档器的选择做成了工厂 make_checkpointer_from_env()（memory/checkpointer.py:24）：本地用内存版，生产按环境变量接 Redis / PostgreSQL。这就是 Day 09 要讲的"Working Memory（工作记忆）"层。

L08

compile 与 invoke：把图跑起来

最后把流程串一遍，你就掌握了任何 LangGraph 图的"读法"：

1

StateGraph(State)

以 State 类型开一张空图。

2

add_node / add_edge / add_conditional_edges

往图里加节点、连普通边和条件边。读一个 agent 的 builder.py 就是读这些调用。

3

compile(checkpointer=...)

编译成可执行图，可选挂存档器。

4

await graph.ainvoke(初始state, config)

跑图。ainvoke 是异步版（本框架全用异步）。返回最终 state。也有 astream 逐节点流式返回（做 SSE 用）。

读代码技巧：以后打开任何一个 agent，直接看它的 builder.py——从 StateGraph(...) 到 .compile() 之间的那段，就是这个 Agent 的完整"流程图定义"。先把节点和边捋清楚，再逐个看节点函数干嘛。这是本框架最高效的读法。
