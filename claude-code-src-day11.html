Day 11 / 共 20 天 · 第 3 周 扩展能力

Slash 命令系统

"/help /model /compact /init" 这些斜杠命令怎么定义、注册、解析分派？今天讲透，并揭示一个大一统洞察：skills、插件命令、MCP prompt 本质是同一种东西。

L01

什么是 Slash 命令

在输入框里以 / 开头的就是斜杠命令，比如 /help（看帮助）、/model（换模型）、/compact（手动压缩上下文）、/clear（清空对话）。它们是不发给模型的本地功能（大多数），或者展开成一段给模型的指令（如 /init）。

核心文件：类型定义 src/types/command.ts、注册表 src/commands.ts、解析 src/utils/slashCommandParsing.ts、派发 src/utils/processUserInput/processSlashCommand.tsx。

L02

三种命令形态

一个 Command（command.ts:219）= 公共基类 + 三选一形态。理解这三种是理解整个系统的钥匙：

type: 'prompt'

展开成一段文本/内容块喂给模型。如 /init（生成 CLAUDE.md 的指令）、技能。

type: 'local'

纯本地逻辑，不查询模型，返回文本/compact 结果。如 /clear、/compact。

type: 'local-jsx'

渲染一个 Ink UI 面板。如 /help、/model、/mcp、/agents。

公共基类 CommandBase（command.ts:177）的关键字段：name、aliases?、description、isEnabled?()、argumentHint?、disableModelInvocation?（禁止模型调用）、userInvocable?（是否允许用户 /xxx 直接调）、loadedFrom（来源：skills/plugin/bundled/mcp…）。

为什么分这三种？ 因为斜杠命令干的事天差地别：有的只是本地清个屏（local）、有的要弹个选择面板（local-jsx）、有的其实是"帮我把这句话展开成给模型的长指令"（prompt）。用一个 type 字段区分，派发时按类型走不同逻辑。local-jsx 的 "jsx" 就是它返回一个 React/Ink 组件当界面。
L03

命令注册表

注册中心 src/commands.ts。核心是 COMMANDS（:297）——注意它是一个 memoize 的函数，返回命令数组，而不是模块级常量：

// commands.ts:297
const COMMANDS = memoize((): Command[] => [
  clearCmd, helpCmd, modelCmd, compactCmd,
  feature('DAEMON') && daemonCmd,     // ← feature 门控，关了就不加载
  // ...
].filter(Boolean))
为什么用函数而非常量？ 因为很多命令的 isEnabled 要读运行时配置（比如某功能开没开）——不能在模块加载那一刻就求值。用函数 + memoize：第一次调用时才计算（此时配置已就绪），之后缓存复用。feature('X') && cmd 这种写法配合构建期死代码消除——关掉的 feature，相关命令代码直接不进产物。

命令来源不止内置。loadAllCommands（:536）并行加载多个来源：内置命令 + bundled skills + 插件命令 + 插件 skills + .claude/skills 目录 skills + workflow 命令。对外主入口 getCommands(cwd)（:563）再按鉴权/enabled 过滤。

L04

懒加载：启动只读元数据

local 和 local-jsx 命令都用懒加载——注册时只声明元数据，真被调用时才 import 实现（command.ts:77）：

// src/commands/clear/index.ts —— 只有元数据 + 一个 load()
export default {
  type: 'local',
  name: 'clear',
  aliases: ['reset', 'new'],
  description: '清空会话历史',
  load: () => import('./clear.js'),   // ← 用到才加载真正的实现
}
为什么懒加载？ 有几百个命令。如果启动时把每个命令的完整实现都加载进来，冷启动会很慢、内存占用大。只加载"元数据"（名字、描述、别名——这些要用来做自动补全和帮助列表），实现代码等你真敲了 /clear 才加载。这跟 Day 02 讲的 cli.tsx fast-path 动态 import 是同一种"按需加载优化冷启动"的思路，贯穿整个项目。
L05

解析 "/x args"

你敲 /model opus，怎么拆成"命令 model + 参数 opus"？parseSlashCommand（slashCommandParsing.ts:25）：

// slashCommandParsing.ts:25
function parseSlashCommand(text) {
  if (!text.trim().startsWith('/')) return null    // 不是斜杠命令
  const words = text.slice(1).split(/\s+/)          // 去掉 /，按空格切
  let name = words[0]                               // 第一个词 = 命令名
  // 特判 MCP 命令：第二个词是 (MCP) 就拼进名字
  const args = words.slice(1).join(' ')             // 其余 = 参数
  return { name, args, isMcp }
}

非常朴素：去掉 /、第一个词是命令名、剩下拼成参数字符串。有个特判——MCP 命令名带 ` (MCP)` 后缀。

L06

派发：按 type 走不同路

解析出命令后，processSlashCommand（processSlashCommand.tsx:427）先判断是不是真命令（不是就当普通消息发给模型，或提示"未知命令"），是就交给 getMessagesForSlashCommand（:691）按 type switch 派发：

J

local-jsx（:732）：command.load() → mod.call(onDone, ctx, args)，返回的 JSX 通过 setToolJSX 渲染成终端面板

L

local（:857）：mod.call(args, ctx)，结果分 skip/compact/text 三种

P

prompt（:938）：command.getPromptForCommand(args, ctx) 拿到内容块，做参数替换 + @-mention 附件解析，作为 user 消息交给模型（fork 上下文的走子代理）

local-jsx 的 onDone 回调：像 /model 弹出的模型选择面板，你选完之后要"往对话里插一条'已切换到 opus'的消息"——这就是 onDone 干的。面板是临时 UI（toolJSX 覆盖层，Day 04），选完调 onDone 收尾、把结果并回对话。prompt 命令的 @-mention 解析：/review @src/app.ts 里的 @文件 会被解析成附件塞进给模型的消息——命令能带上文件内容。
L07

大一统洞察：它们都是 Command

💡 关键洞察：skills、插件命令、bundled 命令、MCP prompt —— 本质上都是 type:'prompt' 的 Command，和你手敲的斜杠命令共用同一套解析/派发管线（processSlashCommand）。

它们的差异只体现在 CommandBase 的几个字段上：

  • loadedFrom：从哪来（skills / plugin / bundled / mcp）。
  • disableModelInvocation：模型能不能自己调它。
  • userInvocable：用户能不能 /xxx 直接调（有些 skill 只让模型调，用户直接调会被拒）。
为什么这个洞察重要？ 因为它把看似五花八门的东西（Day 13 的 skills、MCP 的 prompt、插件命令）统一成了一个概念——都是"一段能被触发、展开成给模型的指令"的 Command。理解了这一点，你就不用分别学 4 套机制；它们只是同一个 Command 接口的不同 loadedFrom。这是优秀抽象的威力：用一个统一模型覆盖多个表面不同的需求。Day 13 讲 skills 时你会看到，一个 SKILL.md 最后就是被包成一个 type:'prompt' 的 Command。
