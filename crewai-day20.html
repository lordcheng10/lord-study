构建、测试与收官串讲

最后一天：测试调试、从零搭 Crew 的清单、Crew vs Flow 决策、常见坑、20 天知识地图、以及 CrewAI 贯穿始终的设计哲学。

L01

测试与调试

# 跑测试（monorepo，用 uv/pytest）
cd lib/crewai && pytest tests/
# 调试：verbose=True 看每一步
crew = Crew(agents=[...], tasks=[...], verbose=True)
# 挂事件监听器（Day 18）打印每个事件，观察全流程
调 Crew 的最佳姿势 ① verbose=True：打印 Agent 每一步的思考、工具调用、结果——看它"想了什么、做了什么"。② 事件监听器（Day 18）：订阅 TaskStarted/Completed 等，自定义打印/记录。③ 先跑单个 Agent（agent.kickoff，Day 02）验证它行为对，再组队。Agent 行为诡异时，verbose 的思考轨迹是第一手线索——看它在哪一步跑偏了。
L02

train / test 命令

CrewAI 有两个特色能力（都用 Day 04 的 copy() 隔离执行）：

  • train：多次运行 Crew，收集人类反馈，"训练"出更好的提示——让 Crew 表现更稳定。
  • test：跑多次、用 LLM 打分评估 Crew 质量——量化"这个 Crew 好不好"。
为什么需要 train/test？ Agent 系统的输出有随机性，"感觉还行"不够——你需要量化评估（test 打分）和持续改进（train 收反馈优化提示）。这是把 Agent 从"玩具 demo"做到"可靠生产系统"的关键工程实践。能自主行动的 AI，必须能被评估和改进。
L03

从零搭一个 Crew 的清单

  • 脚手架：crewai create crew my_project（Day 19）
  • 定义 agents：在 config/agents.yaml 写 role/goal/backstory（Day 02/19）
  • 定义 tasks：在 config/tasks.yaml 写 description/expected_output，配 agent、context（Day 03）
  • 配工具：给需要的 agent 配 tools（Day 14）
  • 选流程：sequential（简单）或 hierarchical（要经理调度）（Day 06）
  • 要精确控制大流程？用 Flow 包起来，某步内嵌 Crew（Day 11）
  • 加增强：需要记忆开 memory、需要资料加 knowledge_sources（Day 16/17）
  • 加护栏：关键任务配 guardrail 保证输出质量（Day 10）
  • 加观测：写事件监听器记录/监控（Day 18）
  • 评估改进：用 test 打分、train 优化（本日）
你现在能驾驭 CrewAI 了 这张清单每一项都对应你学过的某一天。从"读懂源码"到"会搭、会配、会调、会评估"，你都具备了。
L04

Crew 还是 Flow？（决策）

  • 纯 Crew：任务开放、创造性强、流程不需要精确控制（"写一篇分析报告"）。让 AI 团队自主发挥。
  • 纯 Flow：流程固定、步骤明确、几乎不需要 AI 自主决策（数据处理管道）。
  • Flow + 内嵌 Crew（推荐组合）：复杂应用——Flow 控制确定性骨架（保证流程正确），关键步骤内嵌 Crew 让 AI 发挥。大多数生产应用的最佳选择。
一句话：需要"AI 自主智能"用 Crew，需要"精确流程控制"用 Flow，两者都要就 Flow 套 Crew。这是 CrewAI 相比其他框架的独特之处——同时提供"自主"和"确定性"两种范式，还能组合。
L05

常见坑速查

  • 顺序模式任务没配 agent：sequential 下每个 task 必须有 agent（Day 04 校验会报错）。
  • 层级模式给经理配了工具：经理只能有委派工具，配普通工具会抛异常（Day 06）。
  • context 依赖后面的任务：会被校验拦下（时间悖论，Day 04/10）。
  • 找不到 ShortTermMemory 等类：已重构为统一记忆（Day 16）。
  • Flow 死循环：@listen 误写成方法自身名，超 max_method_calls 报错（Day 11）。
  • 忘了防失控：给 agent 配 max_iter、给 crew 配 max_rpm（Day 02/04）。
  • 提示词硬编码在 Python：改用 YAML 分离（Day 19），迭代更快。

L07

贯穿始终的设计哲学

① 角色扮演：role+goal+backstory 是 Agent 的一等公民，把"给 AI 身份"这个提示词技巧做成框架核心。
② 声明式校验（fail-fast）：大量 Pydantic validator 在 kickoff 前抓配置错误——错误尽早暴露。
③ 两种范式并存：Crew（自主）+ Flow（确定性），还能组合——覆盖从创造性到流程化的所有场景。
④ 复用已有抽象：委派做成工具、记忆用 Flow 实现、协作复用 function-calling——不重复造轮子。
⑤ 事件驱动可观测：全流程发事件，日志/监控/集成靠监听器零侵入挂载（AOP）。
⑥ 配置与代码分离：YAML 放提示词配置，Python 放逻辑——迭代快、协作易、可工程化。
⑦ 处处防失控：max_iter / max_rpm / max_usage_count / max_method_calls / guardrail——能自主/循环的地方必有刹车。
这些哲学和你在 eino、OpenHands 教程里学的高度重合——统一抽象、fail-fast、面向接口、成本经济学、事件可观测。因为它们是所有优秀 AI Agent 框架的通用语言。学了三个框架，你已经能看穿第四个。
