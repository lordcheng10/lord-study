存储 StorageContext

建好的索引数据存在哪、怎么持久化复用？今天拆 StorageContext——它统管三个存储：docstore（文档/Node）、index_store（索引结构）、vector_store（向量）。理解这"三件套"，就理解了 LlamaIndex 的数据落地。

L01

三件套

存储存什么
docstore（文档库）Node/Document 本身（文本、metadata、关系）
index_store（索引库）索引结构（index_struct：哪些 Node 属于哪个索引、映射）
vector_store（向量库）Node 的 embedding 向量（Day 09）
为什么要拆成三个？ 三种数据性质不同：文本/metadata 是普通数据（放文档库）；向量是高维数组、要专门的相似度检索（放向量库，Day 09）；索引结构是"目录/映射"（放索引库）。拆开存的好处：各用最合适的后端——向量放专业向量数据库（Pinecone/Chroma）、文档放 Redis/MongoDB、索引放本地。回想 Day 07：VectorStoreIndex 的向量在 vector_store、文本在 docstore、结构在 index_store——就是这三件套。
L02

docstore

storage/docstore/：BaseDocumentStore + SimpleDocumentStore（默认，内存/JSON）。存 Node，按 id_ 存取；还记录 ref_doc_info（Node 属于哪个原文档，用于 Day 05 的去重更新）。

docstore 是"Node 的仓库" 切好的每个 Node 存进 docstore（按 id_ 索引）。检索时向量库返回 Node id，再从 docstore 取出完整 Node（文本+metadata）给 LLM。为什么不把文本直接存向量库？因为有些向量库只擅长存向量、不适合存大文本，分开更灵活。ref_doc_info 记"这些 Node 来自哪个 Document + 文档 hash"——支撑 Day 05 的增量更新（判断文档变没变）。
L03

index_store

storage/index_store/：BaseIndexStore + SimpleIndexStore。存 index_struct（Day 07）——每个索引的元结构。

读法：一个 StorageContext 可以承载多个索引（比如一个向量索引 + 一个摘要索引共享同一批 docstore 的 Node）。index_store 记"每个索引的结构和它包含哪些 Node id"。轻量的"目录",指向 docstore 里的实际 Node。
L04

vector_store

vector_stores/：BasePydanticVectorStore + SimpleVectorStore（默认，内存）。存 embedding，提供相似度查询（Day 09 精读）。

向量库是 RAG 的"检索引擎" 它专门存向量、并能快速"给一个查询向量、找最相似的 k 个"。默认 SimpleVectorStore 用内存 + 暴力算相似度（小数据够用）；生产用专业向量库（Chroma/Qdrant/Pinecone/Milvus，百万向量也快）。换向量库只需换 integration。明天专门拆 SimpleVectorStore 的 query。
L05

StorageContext

storage/storage_context.py:53 的 StorageContext 把三者打包：

storage_context = StorageContext.from_defaults(
    docstore=SimpleDocumentStore(),
    index_store=SimpleIndexStore(),
    vector_store=ChromaVectorStore(...),   # 换成专业向量库
)
index = VectorStoreIndex.from_documents(docs, storage_context=storage_context)
读法：from_defaults（:53+）不传就全用 Simple*（内存版，适合入门/测试）；传入就用你指定的后端。索引通过 StorageContext 读写数据——它是"存储的统一门面"。Day 01 的 from_documents 没传 storage_context 就用默认全内存（所以重启数据没了——要 persist）。
L06

persist / 加载

# 持久化到磁盘
index.storage_context.persist(persist_dir="./storage")
# 下次加载（不用重新嵌入！）
from llama_index.core import StorageContext, load_index_from_storage
storage_context = StorageContext.from_defaults(persist_dir="./storage")
index = load_index_from_storage(storage_context)
persist 省下重新建库的时间和钱 建库要嵌入（花钱花时间）。persist 把三件套存到磁盘（docstore.json/index_store.json/向量文件）。下次直接 load_index_from_storage 加载——不用重新读文档、切块、嵌入。Simple* 版存成 JSON 文件；用专业向量库时向量已在库里（Chroma 等自己持久化），只需 persist docstore/index_store。这是"建库一次、多次使用"的关键。
L07

可插拔后端

三件套每个都是"接口 + 多实现"：docstore 可用 Simple/Redis/MongoDB/Postgres；index_store 同理；vector_store 有几十种（Chroma/Qdrant/Pinecone/Weaviate/pgvector…）。

从"玩具"到"生产"只需换后端 开发时全用 Simple*（内存/JSON，零依赖）；上生产换成专业后端（向量库用 Qdrant、文档库用 Redis）——代码几乎不变，只在 StorageContext.from_defaults 换实现。这又是"接口统一、实现可换"（本系列反复出现的设计）。所以你能用同一套 LlamaIndex 代码，从笔记本上的原型平滑扩展到生产集群。
