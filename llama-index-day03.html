Day 03 / 共 20 天 · 第 1 周 RAG 全景与数据摄入

读取数据 Reader

RAG 第一步：把各种格式的数据（txt/pdf/docx/网页/数据库）读成统一的 Document。今天精读 SimpleDirectoryReader——最常用的 Reader，看它怎么遍历目录、按文件类型选提取器、并行加载。

L01

Reader 的职责

Reader 把"外部数据源"转成 List[Document]。readers/ 里有 SimpleDirectoryReader（文件系统）、StringIterableReader 等，更多在 integrations（PDF/Notion/数据库/网页…）。

统一入口：不管什么源，都变成 Document 你的数据可能是本地文件、网页、数据库、API……格式千差万别。Reader 的职责就是"把它们统一读成 Document"（Day 02 的数据结构）。之后的流程（切块/嵌入/索引）只认 Document，不管它原来是 PDF 还是网页。这就是"适配器模式"——把异构数据源适配成统一的 Document 接口。300+ 集成里很大一部分就是各种 Reader。
L02

BaseReader 接口

readers/base.py 的 BaseReader 核心方法就一个：load_data(...) -> List[Document]（可选 lazy_load_data 惰性版）。

读法：接口极简——所有 Reader 只需实现"怎么把我的源读成 Document 列表"。PDF Reader 用 PDF 库解析、Notion Reader 调 Notion API、数据库 Reader 跑 SQL——但对外都是 load_data() → List[Document]。简单统一的接口是生态繁荣（300+ Reader）的基础。
L03

SimpleDirectoryReader

readers/file/base.py:208：class SimpleDirectoryReader(BaseReader, ResourcesReaderMixin, FileSystemReaderMixin)——读一个目录下的所有文件。构造参数：input_dir（目录）、recursive（递归子目录）、required_exts（只读某些后缀）、exclude（排除）、file_extractor（自定义提取器）。

最常用的入门 Reader Day 01 的"5 行 RAG"第一行 SimpleDirectoryReader("data").load_data() 就是它——把 data/ 目录下所有文件读成 Document。它会自动识别文件类型（.pdf/.docx/.md/.txt…）选对应的解析器。用 fsspec 支持本地和云存储（S3 等）——不只本地文件。
L04

file_extractor 分派

不同后缀用不同提取器。SimpleDirectoryReader 有个 file_extractor 映射（后缀 → Reader），如 .pdf → PDFReader、.docx → DocxReader。没有专用提取器的当纯文本读。

"按类型分派"很自然 PDF 要用 PDF 库解析、Word 要用 docx 库、Markdown 直接读文本——一个目录里混合各种格式，SimpleDirectoryReader 按后缀选对应提取器。这些专用提取器大多在 integrations 里（llama-index-readers-file）。你也能传自定义 file_extractor 覆盖默认——比如用 LlamaParse（官方的强力 PDF 解析）替换默认 PDF 提取器。
L05

load_data 并行

readers/file/base.py:718-760：

def load_data(self, show_progress=False, num_workers=None, fs=None) -> list[Document]:
    load_file_with_args = partial(SimpleDirectoryReader.load_file,
        file_metadata=self.file_metadata, file_extractor=self.file_extractor, ...)
    if num_workers and num_workers > 1:      # 多进程并行加载
        num_cpus = multiprocessing.cpu_count()
        if num_workers > num_cpus: num_workers = num_cpus   # 不超过 CPU 数
        # 用进程池并行读多个文件
    # ...每个文件 → load_file → 若干 Document
为什么要并行？ 读 1000 个 PDF，一个个读很慢（解析 PDF 是 CPU 密集）。num_workers 让多个文件并行解析（多进程），大幅加速。还贴心地"不超过 CPU 核数"（超了没意义还抢资源）。一个文件可能产出多个 Document（比如 PDF 每页一个）。show_progress 显示进度条（大批量读时有用）。
L06

file_metadata

SimpleDirectoryReader 给每个 Document 自动填 metadata（文件名、路径、文件类型、大小、创建/修改时间）。可传 file_metadata 函数自定义。

读法：回想 Day 02——metadata 很重要（影响嵌入和溯源）。Reader 阶段就把"文件名/路径"存进 metadata，这样检索到某个 Node 时能追溯"来自哪个文件"。filename_as_id 选项可用文件名当 Document 的 id_（方便去重/更新）。好的 metadata 从读取阶段就要设计好。
L07

LlamaHub 生态

官方的 LlamaHub 有几百个 Reader（Notion/Slack/Google Drive/数据库/GitHub/网页爬虫…），都在 integrations 里、都实现 BaseReader.load_data。

"任何数据都能进 RAG" 想把 Notion 知识库做成问答？装 llama-index-readers-notion。想爬网页？装 web reader。想读数据库？装 database reader。它们全都产出 Document，无缝接入后续流程。这就是统一 BaseReader 接口的威力——生态贡献者只需实现一个 load_data，就能让 LlamaIndex 支持一种新数据源。你的项目要接什么数据，去 LlamaHub 找对应 Reader 即可。
